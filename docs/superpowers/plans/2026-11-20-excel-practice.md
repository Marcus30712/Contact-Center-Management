# 미소의 엑셀 연습 (3단계) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** An `excel/` page with 11 lessons a new team lead completes on a phone without typing: choice, chip blanks, formula-card building, cell picking and menu-step ordering, graded against Miso's example call table by a small formula calculator.

**Architecture:** A pure formula calculator (`excel/formula.js`) evaluates formulas against a sheet object. Lesson data (`excel/data.js`) is generated from the two confirmed copy files by a throwaway script and checked against them by tests. Pure grading/progress logic sits in `excel/engine.js`; DOM in `excel/render.js` and `excel/sheet.js`; wiring in `excel/app.js`. Same patterns as `practice/` and `sop-library/`.

**Tech Stack:** vanilla ES modules, node --test + jsdom, Playwright browser check; no build.

**Spec:** `docs/superpowers/specs/2026-11-20-excel-practice-design.md`; copy `…-excel-practice-copy.md` (Korean, confirmed) and `…-excel-practice-copy.en.md` (English).

## Global Constraints
- All wording = the two copy files exactly; English has no Hangul; every string `{ko, en}`.
- The example table and every result value come from the copy files; the English sheet uses English text values (Team A, romanized names), same numbers.
- Calculator scope = design §5.3 (functions SUM, AVERAGE, MIN, MAX, COUNT, ROUND, COUNTIF, COUNTIFS, SUMIF, SUMIFS, AVERAGEIFS, IF, XLOOKUP, VLOOKUP, INT, MOD, TEXT with "0%", "0.0%", "m:ss"; TRUE/FALSE; ""; & ; comparisons; $ refs). Anything else is an error, graded wrong, never a throw.
- Numbers equal within 1e-9; text exact.
- Build: line starts with a fixed `=`; ≤10 cards per question.
- Progress `excel-practice:v1` `{ completed: [lessonId], scores: { lessonId: 0–6 } }` (first-try right count, keep best); every storage call in try/catch.
- Miso: smile (cards), think, joy, worry, proud from `assets/miso/`, with alt text.
- After runtime file changes run `python3 tools/sw_list.py`; suite `cd agent-lifecycle && npm test` (baseline 297) and `python3 agent-lifecycle/scripts/browser_check.py` stay green.

## Review Focus
1. Equivalent answers: a build with conditions in another valid order (e.g. COUNTIFS pairs swapped) must grade right; tested in Task 3 with 4-6 and 5-5 swaps.
2. Half-built or nonsense lines (`)` first, two ranges in a row, empty line, unbalanced brackets) must grade wrong without throwing (Task 1 error tests, Task 4 render test).
3. Steps with `[any order]` accept both orders and nothing else (Task 3).
4. Narrow phones: 7-column table and 10 cards at 320px don't push the page sideways (Task 5 browser check).
5. Switching language mid-question keeps the question and re-grades against that language's sheet (Task 4 test).
