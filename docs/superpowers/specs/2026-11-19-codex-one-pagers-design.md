# Codex 원페이저 — 설계 문서

작성일: 2026-11-19 · 상태: 승인됨 (2026-11-19)

## 1. 의도와 이유

BPO Contact Center Operation Codex 2.0의 네 장을 장마다 한 장짜리 인터랙티브 화면(원페이저)으로 만든다. 한눈에 전체를 보고, 궁금한 곳을 누르면 자세한 내용이 펼쳐지는 형식이다.

1. 운영 최적화 4대 원칙
2. 5대 핵심팀 청사진
3. 커리어 매트릭스
4. 직무별 일일 업무 가이드

대상은 지금까지와 같은 신입 팀장이다. 강의(라이프사이클, SOP 라이브러리)가 "순서대로 배우는" 형식이라면, 원페이저는 "필요할 때 펼쳐 보는" 참고 형식이다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 첫 화면 카드 1장 "Codex 원페이저"에서 들어가, 원페이저 4장을 오간다. 원페이저마다 주소가 따로 있다.
- 각 원페이저는 처음에 요약만 보이고, 누르면 상세가 펼쳐진다. 키보드와 화면 낭독기로도 쓸 수 있다.
- 한국어/영어. 언어 선택은 다른 주제와 공유한다. 휴대폰(320px)부터 PC까지, 밝은/어두운 화면.
- 내용은 데이터 파일로 두어 나중에 학습 앱으로 옮길 수 있게 한다.

**비목표**
- Codex의 다른 장(관리 프로토콜, 성장 로드맵, 데이터 스킬 가이드, 소프트 스킬, 멘토십). 필요해지면 같은 틀로 추가한다.
- 인쇄용 레이아웃, 검색, 진행 기록.
- 새 용어집 용어 추가. 팀별 KPI 가운데 용어집에 없는 것(Time to Fill 등)은 원페이저 안에서 정의한다.

**반목표**
- Codex의 숫자를 업계 기준처럼 보이게 쓰는 것. 하루 일정의 시각, 시간 비중, 승진 조건의 기간·인원은 "예시"로 표시하고 "센터마다 다를 수 있다"는 안내를 둔다.
- 특정 국가의 법 언급. 인사팀 역량의 "노동법"은 "노동 관련 법·제도"로 바꾼다 (4.1).
- 이미 정한 정의와 어긋나는 내용. 예: Codex 5대 핵심팀의 Shrinkage 정의("예상치 못한 이탈 시간 비율")는 이 Knowledge Base에서 확정한 정의(콜을 받을 수 없는 모든 시간의 비율, 계획/계획 외 포함)로 쓴다.

## 3. 접근 방식

- **A. 첫 화면 카드 1장 + 안쪽에 원페이저 4장** — 원페이저마다 주소가 있고 위쪽 탭으로 오간다. 공통 부분(펼치기, 탭)은 한 번만 만든다. 첫 화면이 9장으로 늘지 않는다.
- B. 첫 화면에 카드 4장 — 찾기는 쉽지만 첫 화면이 9장이 되고, 하나의 Codex에서 나왔다는 연결이 사라진다.
- C. 긴 페이지 한 장 — 만들기는 쉽지만 "장마다 원페이저"와 맞지 않고 휴대폰에서 너무 길다.

**사용자 선택: A.**

## 4. 결정된 사항

### 4.1 사용자 결정
- 방식 A. 문안은 Codex 문장을 그대로 쓰고(이모지 제거, 설명 3문장 이내로 다듬기), 한국어 검토는 "Codex에서 바꾼 곳 목록"으로 한다.
- 숫자는 "예시"로 표시하고 "센터마다 다를 수 있다"고 안내한다. 용어집에 있는 KPI·직급 이름은 링크한다. 커리어 매트릭스는 라이프사이클 레슨 6, 팀장의 하루는 SOP 라이브러리 1:1 코칭과 연결한다.
- 인사팀 역량의 "노동법 기초 지식", "노동법 깊은 이해", "노동법 적용"은 "노동 관련 법·제도 이해" 계열로 바꾼다.
- 이전부터 이어지는 규칙: 커밋·푸시·병합은 승인 후, MIT, 금지어, 용어 표기.

### 4.2 화면 (제작자 제안)

주소: `codex/`. 제목: **Codex 원페이저 · Codex One-Pagers**. 목록 화면에 원페이저 4장의 카드(제목, 한 줄 설명). 각 원페이저 위쪽에 4개 탭과 "목록" 링크.

**① 운영 최적화 4대 원칙** (`#principles`)
- 처음: 원칙 카드 4장 — 번호, 제목(예: "'하드코딩' 줄이기 → Master SOP 구축"), 한 줄 요약.
- 누르면: 카드가 펼쳐져 **문제점 → 최적화 → 실제 사례** 세 칸. "모두 펼치기 / 모두 접기" 버튼.
- 한 줄 안내: Codex는 운영을 코드에 빗대어 "버그(문제점)를 고치는 최적화"로 설명한다.

**② 5대 핵심팀 청사진** (`#teams`)
- 처음: 팀 5개 카드 — 팀 이름과 핵심 미션 한 줄. 운영팀 카드에 "당신의 팀" 표시.
- 누르면: 그 팀의 상세 — 역할(R&R), 주요 KPI(이름, 한 줄 정의, 용어집에 있으면 링크), 핵심 업무 흐름(화살표로 이어진 단계).
- 한 번에 한 팀만 펼친다 (다른 팀을 누르면 바뀜).

**③ 커리어 매트릭스** (`#career`)
- 처음: 팀 탭 5개(기본: 운영팀) + 직급 사다리(아래에서 위로). 운영팀의 Team Lead에 "지금 당신" 표시.
- 누르면: 직급 상세 — 핵심 역할, 주요 역량(업무 역량 / 소프트 스킬로 나눔, Codex의 "/" 기준), 다음 단계로 가는 조건(맨 위 직급은 없음).
- 아래 안내: "조건의 기간과 인원은 Codex의 예시 기준이며 센터마다 다를 수 있습니다." + 라이프사이클 레슨 6(경력 개발) 링크.

**④ 직무별 일일 업무 가이드** (`#daily`)
- 처음: 직무 탭 5개(Agent, SME, 팀장, 부매니저, 매니저; 기본: 팀장) + 09:00–18:00 하루 시간 막대(업무별로 색과 무늬, 점심은 회색) + 업무 4가지 목록(시간 비중 막대).
- 누르면: 시간 막대의 칸이나 목록의 업무를 누르면 그 업무의 빈도, 시간 비중, 주요 결과물이 보인다. 막대 칸과 목록이 같은 업무를 함께 강조한다.
- 팀장 탭에 SOP 라이브러리 "1:1 코칭" 링크. 아래 안내: "시각과 시간 비중은 예시이며 센터마다 다를 수 있습니다."

- **하루 일정과 업무 4가지가 맞지 않는 곳 (제작자 결정)**:
  - 부매니저와 매니저의 17:30–18:00("주요 이메일 회신 및 실행 계획 점검", "장기 전략 구상 및 하루 업무 마무리")은 업무 4가지 어디에도 속하지 않는다. 시간 막대에 "그 밖의 업무" 칸으로 그대로 두고, 누르면 Codex 문장을 보여 준다. 목록에는 넣지 않는다.
  - 목록의 시간 비중은 Codex가 적은 값("약 70%")을 그대로 쓴다. 하루 일정에서 계산한 값과 다를 수 있다 (예: Agent 고객 응대는 일정상 8시간 중 6시간). 주간·월간 업무가 섞여 있기 때문이므로 안내 한 줄을 둔다: "시간 비중은 한 주 전체를 기준으로 한 값이라, 하루 일정과 다를 수 있습니다." 테스트는 Codex 값의 합이 100%인지와 일정이 빈틈없이 이어지는지를 따로 확인한다. 점심은 비중에 넣지 않는다.
- **"당신의 팀"(운영팀)과 "지금 당신"(Team Lead) 표시**: 데이터 파일의 설정값으로 둔다 (제작자 결정).

### 4.2-1 확정 뒤 추가된 결정 (사용자, 2026-11-19)
- **앞/뒤 링크**: 각 원페이저 아래에 "앞에 보면 좋은 것 / 다음에 보면 좋은 것" 링크를 둔다. 대상과 한 줄 이유는 문안 파일의 "앞/뒤 링크".
- **Pip Decks는 아이디어만**: 카드 덱의 글, 그림, 레이아웃, 이름은 쓰지 않는다. 가져오는 아이디어는 "요약 앞면 → 누르면 자세한 뒷면", "번호가 붙은 단계", "분류 표시", "앞/뒤로 이어지는 링크"뿐이며, 화면은 이 사이트의 디자인으로 새로 만든다.
  - 앞면: 분류 칩(글자 + 색), 번호, 제목, 한 줄. 뒷면은 카드가 아래로 펼쳐지는 방식(뒤집기 애니메이션 없음 — 글을 읽기 쉽고 화면 낭독기에 맞다).
  - 업무 흐름은 번호 원과 화살표로 세로/가로 자동 배치. 분류는 색만이 아니라 글자로도 표시.
  - 펼친 뒤에도 한 줄 길이는 읽기 좋은 폭(약 40자)을 넘지 않게 한다.
- **상황별 길잡이**: 이번 범위가 아니다. 다음 주제로 둔다.

### 4.3 문안 원칙 (제작자 제안)
- 한국어는 Codex 문장 그대로. 바꾸는 경우만 목록으로 만들어 검토받는다: 이모지 제거, 3문장 초과 설명 다듬기, 4.1의 법 표현, 2의 Shrinkage 정의, 숫자 앞 "예시" 표시, 용어 표기 통일(AHT = 평균 처리 시간, Attrition = 퇴사율 등).
- 영어는 한국어 확정 뒤 번역한다. 직급·KPI 이름처럼 Codex가 영어로 쓴 것은 그대로 둔다.

### 4.4 함께 바꾸는 곳
- 첫 화면 카드 1장(6장이 됨), README, LOG.md 14번.
- 용어집은 바꾸지 않는다 (원페이저에서 용어집으로 링크만).

## 5. 만드는 방법 (제작자 선택)

- 새 폴더 `codex/`: `index.html`, `app.js`(주소에 따라 목록 또는 원페이저), `ui.js`(화면 문구), `render/`(`principles.js`, `teams.js`, `career.js`, `daily.js`, 공통 `parts.js` — 탭, 펼치기 버튼), `data/`(`principles.js`, `teams.js`, `career.js`, `daily.js`), `codex.css`.
- 재사용: `agent-lifecycle`의 `dom.js`(h, s), `i18n.js`, `langToggle.js`, `styles.css`; 용어집 `terms.js`(링크 확인용).
- 펼치기는 `<button aria-expanded>` + 연결된 영역. 탭은 버튼 묶음(`aria-pressed`), 화살표 키로 이동.
- 시간 막대는 SVG가 아니라 CSS 비율 막대(칸 너비 = 시간 비율). 칸은 버튼이고, 화면 낭독기에는 "10:30–12:30, 팀원 1:1 코칭 세션" 식으로 읽힌다.
- 데이터 점검 테스트: 모든 문구 한국어·영어, 금지어, 설명 3문장 이내, 숫자+단위가 있는 설명에는 "예시", 하루 일정이 09:00–18:00을 빈틈없이 잇는지, 직무별 시간 비중 합이 100%인지, 용어집 링크가 실제 용어인지, Codex 단계 수(원칙 4, 팀 5, 직급 팀별 3–5, 직무 5×업무 4).
- 테스트는 `agent-lifecycle/tests/codex.test.js`. 브라우저 점검에 항목 추가.
