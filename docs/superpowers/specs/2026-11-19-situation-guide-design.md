# 팀장 상황별 길잡이 — 설계 문서 (짧은 문서)

작성일: 2026-11-19 · 상태: 승인됨 (2026-11-19)

## 1. 의도와 이유

신입 팀장이 현장에서 막혔을 때 "지금 무엇을 봐야 하지?"를 바로 찾게 한다. 새 설명을 쓰지 않고, 이미 있는 강의·SOP·원페이저·실험실·용어집으로 안내하는 길잡이다.

## 2. 목표 · 비목표 · 반목표

- **목표**: 한 화면에서 상황 17개를 훑고, 두 번 눌러 갈 곳에 닿는다. 묶음 칩으로 좁힐 수 있다. 한국어/영어, 320px–PC, 키보드·화면 낭독기.
- **비목표**: 질문으로 좁히는 방식(B), 검색(C), 새 설명 글, 진행 기록.
- **반목표**: 상황마다 해결책을 직접 써서 기존 내용과 겹치거나 어긋나는 것.

## 3. 접근 방식

- **A. 묶음별 카드 목록 + 묶음 칩** — 전체를 한눈에, 두 번 눌러 도착. 원페이저의 펼치는 카드·칩 재사용. **사용자 선택.**
- B. 질문으로 좁혀 가기 — 친절하지만 17개에서는 A보다 한 단계 느리고 다른 상황으로 돌아가기 번거롭다. 상황이 40–50개로 늘면 더한다.
- C. 증상 검색 — 같은 뜻의 여러 말을 관리해야 해 17개에는 과하다.

## 4. 결정된 사항

**사용자 결정**: 상황 17개와 연결(5장의 표, 확정), 방식 A.

**제작자 결정**
- 새 주제 `guide/`. 첫 화면 맨 위에 "어디서부터 볼까요?" 카드.
- 묶음 칩은 하나만 고르는 탭(전체 + 5개). 고른 묶음만 보이고, 펼친 카드는 언어를 바꿔도 유지된다.
- 연결은 원페이저의 앞/뒤 링크와 같은 모양. 링크 글자는 도착하는 곳의 제목.
- 원페이저 안의 특정 항목으로 바로 가기 위해 Codex 원페이저 주소에 `#teams-<팀>`, `#principles-<원칙>`, `#daily-<직무>`를 더한다 (그 항목이 열린 채로 열림). 없는 항목은 지금처럼 목록으로 간다.
- 영어는 한국어 확정 뒤 번역. US spelling.
- 공통 코드는 `codex/render/parts.js`를 그대로 쓴다.

## 6. 성공 확인

- 테스트: 17개 상황과 링크가 이 문서의 표와 같다, 모든 주소가 실제로 있는 곳이다(레슨·SOP id, 원페이저 항목, 용어집 id), 칩이 묶음을 좁힌다, 영어에 한글이 없다.
- 브라우저 점검: 링크 34개가 모두 제목이 있는 화면을 열고, `#teams-ta` 같은 주소는 그 팀이 열린 채로 열린다, 320px에서 넘치지 않는다.
- 사용자가 GitHub Pages에서 확인.
