# 상담사 SOP 라이브러리 — 한국어 문안 초안

작성일: 2026-11-27 · 상태: 승인 (2026-11-27, [확인] 3곳은 사용자 답으로 채움) · 설계: `2026-11-27-agent-sop-design.md`

공통 원칙: 스텝은 3문장 이내로 씁니다. 출처 없는 숫자에는 "예시"를 붙입니다. 시점은 "당신 = 상담사 지민"이 아니라, 지민을 따라가는 3인칭입니다(상담사 첫걸음과 같음). 레슨마다 마지막 스텝은 미소의 "그때 알았더라면" 한마디입니다.

다른 강의와 겹치지 않게 하는 방법:
- 상담사 첫걸음은 처음 반년의 적응을 다룹니다. 이 강의는 **절차 하나하나를 순서대로** 다룹니다. 무엇을, 언제, 누구에게, 어떻게 남기는지가 중심입니다.
- 직무전문가·팀장 SOP와 같은 절차는 상담사가 맡는 부분만 다루고, 레슨마다 "같은 일을 직무전문가·팀장은 이렇게 받습니다" 한 줄로 이어 줍니다.

## 레슨 1. 에스컬레이션 요청하기

| 항목 | 한국어 |
|---|---|
| 제목 | 에스컬레이션 요청하기 |
| 짧은 이름 | 에스컬레이션 |
| 부제 | 내 권한으로 안 될 때, 고객이 다시 말하지 않게 넘깁니다. |
| 누가 | 상담사 → 직무전문가 → 팀장 |
| 노드 | 혼자 풀어 보기 · 고객에게 안내 · 한 번에 요청 · 기록과 이어 받기 |

스텝:

1. 이 절차의 목적은 내 권한으로 풀 수 없는 문의를 직무전문가에게 빠르게 넘기면서, 고객이 같은 이야기를 다시 하지 않게 하는 것입니다.
2. 지민이 화가 난 고객의 보상 요청 전화를 받습니다. 첫 단계는 혼자 풀어 보기입니다. 고객의 말을 끝까지 듣고, 표준 절차와 내 권한 안에서 먼저 풀어 봅니다.
3. 둘째 단계는 고객에게 안내입니다. 내 권한 밖이면 논쟁하지 않고, 담당자에게 전달하겠다고 알리고 얼마나 기다리는지 안내합니다.
4. 셋째 단계는 한 번에 요청입니다. 메신저나 손을 들어 하린에게 고객 요청, 이미 해 본 것, 고객 상태를 한 번에 전합니다.
5. "보상 돼요?"처럼 묻기만 하면 하린이 다시 물어야 하고, 그동안 고객은 기다립니다.
6. 넷째 단계는 기록과 이어 받기입니다. 티켓에 에스컬레이션 표시를 하고 고객이 한 말과 감정까지 사실대로 적습니다. 하린의 답을 받으면 고객에게 결과를 이어서 안내합니다.
7. 하린은 승인 권한 안이면 바로 승인하고, 권한 밖이면 수진 팀장에게 넘깁니다. 직무전문가 SOP의 에스컬레이션 승인, 팀장 SOP의 고객 불만 에스컬레이션이 이 다음 부분입니다.
8. 미소의 한마디: 저는 에스컬레이션을 넘기면 제 일은 끝난 줄 알았어요. 기록을 자세히 남긴 날일수록 고객이 덜 화내고, 저도 덜 불려 다녔더라고요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 지민의 권한으로 풀 수 없는 요청입니다. 하린에게 가장 알맞은 요청은 무엇일까요? |
| 보기 a (오답) | "보상 요청인데 승인 되나요?" 하고 먼저 묻고, 답을 기다린다. |
| a 피드백 | 이렇게 물으면 하린이 무엇을 확인했는지 다시 물어야 하고, 그동안 고객이 기다립니다. |
| 보기 b (정답) | 다시 묻지 않게, 고객 요청·해 본 것·고객 상태를 한 번에 전한다. |
| 보기 c (오답) | 화가 난 고객의 통화를 하린에게 바로 돌려, 처음부터 하린이 직접 받게 한다. |
| c 피드백 | 상황을 모르는 사람에게 바로 돌리면 고객이 처음부터 다시 말해야 합니다. 먼저 요청하고 기다림을 안내합니다. |
| 해설 | 요청을 한 번에 전하면 하린이 바로 판단하고, 고객은 같은 말을 되풀이하지 않습니다. |
| 2번 질문 | 하린이 승인해 주었습니다. 지민이 마지막으로 할 일은 무엇일까요? |
| 보기 a (오답) | 승인을 받았으니 바로 다음 문의를 받는다. |
| a 피드백 | 고객에게 결과를 이어서 안내하고 기록을 남겨야 끝납니다. |
| 보기 b (오답) | 고객에게 결과만 짧게 알리고, 티켓에는 "승인 완료"라고만 적는다. |
| b 피드백 | 누가 왜 승인했는지 없으면 같은 요청이 다시 왔을 때 아무도 판단 근거를 찾을 수 없습니다. |
| 보기 c (정답) | 고객에게 결과를 안내하고, 티켓에 승인자와 이유를 적는다. |
| 해설 | 에스컬레이션은 고객에게 결과를 알리고 승인자와 이유를 남길 때 끝납니다. |
| 다음 레슨 연결 | 넘겨야 하는 문의가 늘 정중한 것은 아닙니다. 다음은 욕설과 폭언이 계속될 때의 절차입니다. |

## 레슨 2. 욕설·폭언 고객 응대와 통화 종료

| 항목 | 한국어 |
|---|---|
| 제목 | 욕설·폭언 고객 응대와 통화 종료 |
| 짧은 이름 | 욕설 응대 |
| 부제 | 참고 버티지 않고, 센터가 정한 순서대로 끝냅니다. |
| 누가 | 상담사 → 직무전문가 또는 팀장 |
| 노드 | 경고 · 승인 받기 · 종료 안내 · 기록 |

스텝:

1. 이 절차의 목적은 욕설과 폭언이 계속될 때 상담사가 혼자 참지 않고, 센터가 정한 순서대로 통화를 끝내고 기록을 남기는 것입니다.
2. 지민의 통화에서 고객이 욕설을 시작합니다. 화가 난 것과 욕설은 다릅니다. 화가 난 고객은 끝까지 듣지만, 욕설은 정해진 절차를 따릅니다.
3. 첫 단계는 경고입니다. 센터가 정한 문구로, 욕설이 계속되면 더 안내할 수 없다고 차분하게 알립니다.
4. 정한 횟수(예시: 3회)를 넘으면 다음 단계로 갑니다. 횟수와 문구는 센터마다 다르니, 내 센터의 기준을 미리 알아 둡니다.
5. 둘째 단계는 승인 받기입니다. 상급자의 승인이 필요한 센터라면, 종료하기 전에 하린이나 수진 팀장에게 말이나 메시지로 승인을 받습니다.
6. 셋째 단계는 종료 안내입니다. 욕설로 더 안내할 수 없어 통화를 종료한다고 알린 뒤 끊습니다. 아무 말 없이 끊지 않습니다.
7. 넷째 단계는 기록입니다. 상담 기록에 경고한 횟수, 승인한 사람, 욕설로 인한 종료를 남깁니다. 끝난 뒤 힘들면 하린이나 수진 팀장에게 잠시 쉬겠다고 말해도 됩니다.
8. 미소의 한마디: 저는 욕을 듣고도 끝까지 참는 게 프로라고 생각했어요. 절차대로 끊는 것도 일이고, 그 기록이 다음 상담사를 지킨다는 걸 늦게 알았어요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 고객이 처음으로 욕설을 했습니다. 지민이 먼저 할 일은 무엇일까요? |
| 보기 a (오답) | 승인을 받아 그 자리에서 바로 통화를 끝낸다. |
| a 피드백 | 첫 욕설에는 먼저 경고합니다. 정한 횟수를 넘었을 때 종료 절차로 갑니다. |
| 보기 b (정답) | 욕설이 처음이니, 센터가 정한 문구로 경고한다. |
| 보기 c (오답) | 고객이 진정할 때까지 아무 말 없이 듣고만 있는다. |
| c 피드백 | 참고 듣기만 하면 욕설이 이어집니다. 정한 문구로 경고하는 것이 첫 단계입니다. |
| 해설 | 욕설은 경고부터 시작합니다. 횟수와 문구는 센터가 정한 기준을 따릅니다. |
| 2번 질문 | 승인을 받아 통화를 종료했습니다. 상담 기록에 무엇을 남길까요? |
| 보기 a (정답) | 경고 횟수, 승인한 사람, 욕설로 인한 종료 |
| 보기 b (오답) | 고객이 한 욕설을 한 글자도 빠짐없이 그대로 |
| b 피드백 | 욕설을 다 옮겨 적을 필요는 없습니다. 절차를 따랐다는 사실(경고, 승인, 종료)을 남깁니다. |
| 보기 c (오답) | 다음 상담사가 조심하도록, "악성 고객"이라는 메모만 |
| c 피드백 | 낙인 같은 메모는 근거가 되지 않고 다음 응대를 흐립니다. 사실을 적습니다. |
| 해설 | 기록에는 절차를 지켰다는 사실을 남깁니다. 그래야 다음에 같은 고객이 와도 근거가 됩니다. |
| 다음 레슨 연결 | 나를 지키는 절차가 하나 더 있습니다. 다음은 아파서 출근할 수 없을 때입니다. |

## 레슨 3. 결근·병가 알리기

| 항목 | 한국어 |
|---|---|
| 제목 | 결근·병가 알리기 |
| 짧은 이름 | 결근 알리기 |
| 부제 | 빨리, 정한 방법으로, 정한 사람에게 알립니다. |
| 누가 | 상담사 → 팀장 (없으면 직무전문가) |
| 노드 | 미리 알리기 · 정한 방법 · 받을 사람 · 서류 보내기 |

스텝:

1. 이 절차의 목적은 아프거나 불가피한 사정으로 출근할 수 없을 때, 팀이 빈자리를 메울 수 있도록 빨리, 정한 방법으로 알리는 것입니다.
2. 새벽에 열이 나서 지민은 출근하기 어렵다고 느낍니다. 아플 때는 쉬어야 합니다. 다만 알리는 방법이 늦거나 틀리면 쉬는 날이 무단결근처럼 남을 수 있습니다.
3. 첫 단계는 미리 알리기입니다. 근무 시작 1~2시간 전(예시)에는 알립니다. 팀이 그 시간에 다른 사람으로 자리를 메울 수 있습니다.
4. 둘째 단계는 정한 방법입니다. 전화, 메시지, 근태 시스템 등 팀이나 센터가 정한 방법으로 알립니다. 동료에게 전해 달라고 하지 않습니다.
5. 셋째 단계는 받을 사람입니다. 수진 팀장에게 직접 알리고, 수진 팀장이 휴가나 병가 중이면 하린에게 알립니다.
6. 사유는 짧고 분명하게 말합니다. 본인이 아프면 "몸이 아파 오늘 출근이 어렵습니다"라고 알리고, 병원에 들른 뒤 진단서를 보내겠다고 덧붙입니다. 예상치 못한 가족이나 개인 사정이면 대략적인 사유를 말하고 긴급 휴가(Emergency Leave)를 요청합니다.
7. 넷째 단계는 서류 보내기입니다. 병가를 알린 뒤 병원에 다녀오면, 진단서 같은 서류를 당일 안에 정한 연락 채널로 수진 팀장이나 하린에게 보냅니다. 제출 기한은 센터마다 다를 수 있으니, 병가도 출결 기록에 남는다는 것과 함께 내 센터의 규칙을 미리 알아 둡니다.
8. 미소의 한마디: 저는 아픈 날 동료에게 "팀장님께 말 좀 전해 줘"라고 했다가 무단결근으로 남은 적이 있어요. 아플수록 정한 방법으로 직접 알리는 게 나를 지키는 길이었어요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 지민이 아파서 출근할 수 없습니다. 가장 알맞은 행동은 무엇일까요? |
| 보기 a (오답) | 옆자리 동료에게 메시지로 팀장님께 결근을 꼭 전해 달라고 부탁해 둔다. |
| a 피드백 | 전달이 늦거나 빠지면 무단결근으로 남을 수 있습니다. 정한 방법으로 직접 알립니다. |
| 보기 b (오답) | 근무 시작 시각에 맞춰 근태 시스템에 결근이라고만 표시한다. |
| b 피드백 | 시작 시각에 알리면 팀이 자리를 메울 시간이 없습니다. 정한 방법으로 미리 알립니다. |
| 보기 c (정답) | 근무 1~2시간 전(예시)에 정한 방법으로 수진 팀장에게 직접 알린다. |
| 해설 | 빨리, 정한 방법으로, 정한 사람에게 직접 알려야 팀이 빈자리를 메우고 내 기록도 지켜집니다. |
| 2번 질문 | 수진 팀장이 휴가 중입니다. 지민은 누구에게 알릴까요? |
| 보기 a (정답) | 팀장이 없으니, 직무전문가 하린에게 알린다. |
| 보기 b (오답) | 휴가 중이어도 수진 팀장에게 알리고 답을 기다린다. |
| b 피드백 | 휴가 중인 팀장은 바로 답하기 어렵습니다. 그날 팀을 맡은 직무전문가에게 알립니다. |
| 보기 c (오답) | 같은 팀 동료 아무에게나 알린다. |
| c 피드백 | 동료는 결근을 처리할 수 없습니다. 팀장이 없으면 직무전문가에게 알립니다. |

## 레슨 5. 지식 베이스 오류 알리기

## 레슨 6. 스크러빙 피드백 받고 고치기

| 항목 | 한국어 |
|---|---|
| 제목 | 스크러빙 피드백 받고 고치기 |

| 노드 | 피드백 받기 · 원인 이해 · 고쳐 쓰기 · 반복 막기 |

스텝:

1. 이 절차의 목적은 직무전문가가 스크러빙에서 찾은 내 티켓의 문제를 이해하고, 같은 일이 다시 나오지 않게 고치는 것입니다.
2. 하린이 지민의 티켓 하나에서 본인 확인 단계가 빠진 것을 찾아 짧게 알려 줍니다. 첫 단계는 피드백 받기입니다. 변명보다 먼저 어느 티켓의 어느 부분인지 확인합니다.
3. 둘째 단계는 원인 이해입니다. 바빠서 건너뛰었는지, 절차를 몰랐는지, 화면에서 놓쳤는지 스스로 원인을 찾습니다.
4. 스크러빙은 누가 잘못했는지 찾는 일이 아니라 원인을 찾는 일입니다. 하린도 팀 채팅방에 이름을 밝혀 올리지 않습니다.
5. 셋째 단계는 고쳐 쓰기입니다. 아직 고객에게 영향이 남아 있으면 하린과 함께 바로잡는 방법을 정합니다. 예를 들어 다시 연락하거나 기록을 보완합니다.
6. 넷째 단계는 반복 막기입니다. 빠뜨린 단계를 화면 옆 체크리스트에 적어 두고, 다음 몇 건은 그 단계를 꼭 확인합니다.
7. 같은 일이 반복되면 하린은 팀장에게 가는 트렌드 요약에 담고, 수진 팀장의 코칭으로 이어집니다. 직무전문가 SOP의 스크러빙이 이 앞부분입니다.
8. 미소의 한마디: 저는 스크러빙 피드백을 받으면 혼난 것 같아서 기분부터 상했어요. 원인을 찾아 주는 거라고 생각을 바꾼 뒤로 같은 실수가 확 줄었어요.

## 레슨 7. 평가 결과 이의 제기

| 항목 | 한국어 |
|---|---|
| 제목 | 평가 결과 이의 제기 |
| 짧은 이름 | 이의 제기 |
| 부제 | 감정이 아니라 근거로, 정해진 경로로 요청합니다. |
| 누가 | 상담사 → 팀장 → QA |
| 노드 | 평가표 읽기 · 근거 모으기 · 팀장에게 요청 · 결과 받아들이기 |

스텝:

1. 이 절차의 목적은 품질 평가에서 납득되지 않는 항목이 있을 때, 근거를 갖추어 정해진 경로로 다시 검토를 요청하는 것입니다.
2. 지민이 받은 평가표에서 안내 항목이 감점되었지만, 지민은 허들에서 들은 대로 안내했다고 생각합니다. 첫 단계는 평가표 읽기입니다. 어느 항목이 어떤 기준으로 감점됐는지 확인합니다.
3. 둘째 단계는 근거 모으기입니다. 티켓 번호, 녹취나 기록의 해당 시점, 근거가 된 공지나 허들 내용을 모읍니다.
4. 셋째 단계는 팀장에게 요청입니다. QA에게 바로 따지지 않고, 평가를 공유받은 뒤 24~48시간(예시) 안에 수진 팀장을 거쳐 근거와 함께 다시 검토를 요청합니다. 기한은 센터마다 다를 수 있습니다.
5. 수진 팀장은 녹취를 함께 듣고, 근거가 있으면 정해진 절차로 QA에 다시 검토를 요청합니다. 팀장 서포트의 QA 지원이 이 다음 부분입니다.
6. 넷째 단계는 결과 받아들이기입니다. 점수가 바뀌든 그대로든 이유를 듣고, 기준이 달랐다면 다음부터 그 기준으로 안내합니다.
7. 이런 사례는 캘리브레이션에서 기준을 맞추는 데 쓰이기도 합니다. 근거 있는 이의는 나만이 아니라 팀 전체의 기준을 바로잡습니다.
8. 미소의 한마디: 저는 억울한 점수를 받으면 동료들한테 불평만 했어요. 근거를 모아 한 번 정식으로 요청해 봤다면, 기준을 이해하는 것도 훨씬 빨랐을 거예요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 지민은 감점이 부당하다고 생각합니다. 가장 알맞은 첫 행동은 무엇일까요? |
| 보기 a (오답) | QA에게 바로 메시지를 보내 왜 감점했는지 따져 묻는다. |
| a 피드백 | QA와 직접 다투면 감정싸움이 되기 쉽습니다. 정해진 경로인 팀장을 통해 요청합니다. |
| 보기 b (정답) | 평가표를 읽고, 티켓·녹취·공지 같은 근거를 모은다. |
| 보기 c (오답) | 평가 기간이 끝나면 다음 달에 한꺼번에 이야기한다. |
| c 피드백 | 이의 제기에는 기한이 있습니다. 근거를 모아 기한 안에 요청합니다. |
| 해설 | 이의 제기는 근거에서 시작합니다. 근거가 있어야 팀장도 QA에 다시 검토를 요청할 수 있습니다. |
| 2번 질문 | 다시 검토했지만 점수는 그대로입니다. 지민에게 알맞은 행동은 무엇일까요? |
| 보기 a (오답) | 납득될 때까지 같은 건으로 다시 이의를 제기한다. |
| a 피드백 | 같은 근거로 다시 요청하면 결과는 같습니다. 이유를 듣고 기준을 이해합니다. |
| 보기 b (오답) | 평가를 믿을 수 없으니 다음부터는 평가표를 보지 않는다. |
| b 피드백 | 평가표는 기준을 배우는 자료입니다. 결과가 마음에 들지 않아도 이유를 읽습니다. |
| 보기 c (정답) | 결과의 이유를 듣고, 다음부터 그 기준으로 안내한다. |
| 해설 | 결과가 그대로여도 이유를 들으면 기준을 알게 됩니다. 이의 제기는 기준을 이해하는 과정이기도 합니다. |

## 레슨 8. 시스템 장애 때 대응

| 항목 | 한국어 |
|---|---|
| 제목 | 시스템 장애 때 대응 |
| 짧은 이름 | 시스템 장애 |
| 부제 | 혼자 고치려 하지 않고, 바로 알리고, 고객에게 정직하게 안내합니다. |
| 누가 | 상담사 → 직무전문가 → 팀장 |
| 노드 | 알아차리기 · 바로 알리기 · 고객 안내 · 기록과 후속 |

스텝:

1. 이 절차의 목적은 상담 시스템이나 고객사 시스템에 장애가 생겼을 때, 혼자 붙잡고 있지 않고 바로 알려 팀 전체가 같은 방식으로 대응하는 것입니다.
2. 지민의 화면에서 주문 조회가 계속 오류를 냅니다. 첫 단계는 알아차리기입니다. 새로고침이나 다시 로그인처럼 정해진 첫 조치(예시)를 해 보고, 그래도 안 되면 장애로 봅니다.
3. 둘째 단계는 바로 알리기입니다. 어떤 화면에서, 언제부터, 어떤 오류가 나는지 하린이나 수진 팀장에게 바로 보고합니다. 두 사람이 오류를 모아 IT 헬프데스크에 티켓을 올려 오류를 알리고 지원을 받습니다.
4. 혼자 고쳐 보려고 오래 붙잡고 있으면, 그동안 같은 오류로 막힌 상담사가 계속 늘어납니다.
5. 셋째 단계는 고객 안내입니다. 하린이나 수진 팀장이 정해 준 안내 문장으로, 지금 확인이 어렵다고 정직하게 알리고 다시 연락할 방법을 안내합니다. 확실하지 않은 복구 시간은 약속하지 않습니다.
6. 넷째 단계는 기록과 후속입니다. 장애로 처리하지 못한 문의는 정해진 표시를 해 두고, 복구되면 순서대로 다시 연락하거나 처리합니다.
7. 하린과 수진 팀장은 장애를 매니저에게도 보고하고, 문의가 몰리면 팀 전체의 대응이 시작됩니다. 팀장 SOP의 대규모 이슈 대응이 이 다음 부분입니다.
8. 미소의 한마디: 저는 장애가 나면 제 컴퓨터 문제인 줄 알고 혼자 재부팅만 했어요. 먼저 알렸다면 팀 전체가 십 분은 더 빨리 같은 안내를 했을 거예요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 정해진 첫 조치를 해 봐도 주문 조회가 계속 오류를 냅니다. 지민이 할 일은 무엇일까요? |
| 보기 a (오답) | 내 컴퓨터 문제일 거라 여기고, 재부팅하고 프로그램을 다시 설치하며 계속 고쳐 본다. |
| a 피드백 | 혼자 붙잡고 있는 동안 막힌 상담사와 고객이 늘어납니다. 첫 조치 뒤에도 안 되면 바로 알립니다. |
| 보기 b (정답) | 어떤 화면에서 언제부터 어떤 오류인지 하린이나 수진 팀장에게 바로 알린다. |
| 보기 c (오답) | 다른 상담사가 알리겠지 하고 기다린다. |
| c 피드백 | 모두가 그렇게 생각하면 아무도 알리지 않습니다. 먼저 본 사람이 알립니다. |
| 해설 | 장애는 먼저 본 사람이 바로, 자세히 알릴수록 오류가 빨리 모여 IT 헬프데스크로 가고, 팀 전체가 같은 방식으로 대응합니다. |
| 2번 질문 | 장애가 계속되는 동안 고객이 언제 되냐고 묻습니다. 가장 알맞은 안내는 무엇일까요? |
| 보기 a (오답) | 고객을 안심시키려고, 늦어도 30분(예시) 안에는 된다고 약속한다. |
| a 피드백 | 확실하지 않은 시간을 약속하면 지키지 못했을 때 불만이 더 커집니다. |
| 보기 b (오답) | 지금은 시스템이 안 된다며 아무것도 해 드릴 수 없다고만 말하고 끊는다. |
| b 피드백 | 이렇게 끝내면 고객은 다시 어떻게 해야 할지 모릅니다. 다시 연락할 방법을 안내합니다. |
| 보기 c (정답) | 정해 준 문장으로 확인이 어렵다고 알리고, 다시 연락할 방법을 안내한다. |
| 해설 | 장애 때는 정직하게 알리고, 다음에 어떻게 될지 안내합니다. 확실하지 않은 시간은 약속하지 않습니다. |
| 마지막 연결 | 상담사 SOP 라이브러리를 마쳤습니다. 배운 순서대로 하면 직무전문가와 팀장이 내 일을 바로 이어받을 수 있습니다. |
