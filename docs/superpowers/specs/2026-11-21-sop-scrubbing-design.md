# SOP 라이브러리: 스크러빙 — 설계와 한국어 문안

작성일: 2026-11-21 · 상태: 방법(A)·순서 승인 2026-11-21 · 2026-11-21 단계 순서 변경 승인(원인 분석 → L1·L2 분류) · 한국어 문안 승인 2026-11-21 (1차 수정 반영: L1 Support 정의, 10번 SLA·품질 영향). 검토 뒤 승인: 연습 배지 조건 "SOP 레슨을 모두 마침", 목록 안내 "팀장이 알아야 할 표준 운영 절차(SOP)…"

## 의도

스크러빙은 처리된 티켓과 쌓여 있는 티켓을 다시 읽고 L1·L2로 분류해 원인을 찾고, BPO 안에서 토의한 뒤 고객사에 보고하거나 건의하는 절차다. 사용자의 설명(2026-11-21)이 기준이다.

- **우선순위:** 1) DSAT → 원인과 개선점을 붙여 고객사에 보고, 2) CSAT → 고객사 제품·서비스에 대한 좋은 인사이트 제공, 3) 미해결·방치 케이스 → SLA 영향을 밝히고, 자체 해결하거나 고객사 허락이 필요하면 프로세스를 만들어 건의.
- **분류 기준(세 종류 공통):** L1 = Product / Process / Support / Customer / Others, L2 = 통제 가능(Control) / 통제 불가(Uncontrol), 비고(Remark) = 추가 정보.
- **자리와 순서(사용자 결정):** 팀장이 직접 하는 절차의 두 번째. 에스컬레이션 → **스크러빙** → 1:1 코칭 → PIP → 캘리브레이션. 이유: 스크러빙 데이터는 QA 품질 감사와 별개로, 팀장이 상담사들이 매일 케이스를 어떻게 처리하는지 흐름을 읽는 자료이고, 코칭과 PIP에 인사이트와 근거를 준다.

- 목표: 스크러빙의 우선순위, 공통 5단계, 원인 분석과 L1·L2 분류를 익히고, 분류를 직접 해 본다.
- 하지 않을 것: 보고서 양식·원페이저(나중에 따로), 특정 회사·고객사·도구 이름, 상황별 길잡이 연결.
- 실패로 볼 것: 고객사 이름이나 실명이 들어가는 것, 수치를 "예시" 없이 기준처럼 쓰는 것, 기존 일곱 레슨의 진도·연습이 깨지는 것.

## 레슨 2. 스크러빙

- 부제: 티켓을 다시 읽고, 원인을 찾아 고객사와 나눕니다.
- 누가: 팀장 · 직무전문가

1. **[전체]** 이 절차의 목적은 처리된 티켓과 쌓여 있는 티켓을 다시 읽고 원인을 찾아, BPO와 고객사가 함께 개선하게 하는 것입니다. QA의 품질 평가와 별개로, 팀장이 상담사들이 매일 케이스를 어떻게 처리하는지 흐름을 읽는 자료가 됩니다. 다섯 단계로 진행합니다.
2. **[대상 고르기]** 첫 단계는 대상 고르기입니다. 당신은 직무전문가와 함께 매일 티켓을 몇 건씩 고릅니다(예시: 하루 3~4건). 우선순위는 DSAT, CSAT, 미해결·방치 케이스 순입니다.
3. **[대상 고르기]** 🟦 DSAT가 먼저인 이유는 불만을 그대로 두면 재문의와 고객 이탈로 이어지기 때문입니다. 오늘 고른 첫 티켓은 지민이 처리한 DSAT 건입니다.
4. **[원인 분석(RCA)]** 둘째 단계는 원인 분석(RCA, Root Cause Analysis)입니다. 팀장과 직무전문가가 티켓을 자세히 조사해 겉으로 보인 문제 뒤의 진짜 원인을 찾고, 그 원인을 한두 문장으로 요약합니다. 🟦 이 DSAT는 상담사들이 반품 절차를 서로 다르게 알고 안내해서 생긴 불만이었고, 지난달 바뀐 절차가 일부 상담사에게 전달되지 않은 것이 원인이었습니다.
5. **[L1·L2 분류]** 셋째 단계는 L1·L2 분류입니다. 요약한 원인을 정해진 분류로 나눠 두면, 나중에 데이터를 추적하거나 필터로 필요한 티켓을 빨리 찾을 수 있습니다. L1은 원인이 어디에 있는지로 나누며 제품(Product), 절차(Process), 지원(Support), 고객(Customer), 기타(Others)가 있고, L2는 BPO가 통제할 수 있는 원인인지, 통제할 수 없는 원인인지로 나눕니다.
6. **[L1·L2 분류]** 지원(Support)은 상담사의 응대 태도(Soft Skill)나 제품·절차 지식의 차이를 가리킵니다. 이번 원인은 상담사의 절차 지식 차이이므로 L1은 Support, L2는 통제 가능입니다. 비고(Remark)에는 어느 안내가 어떻게 달랐는지 적습니다.
7. **[내부 토의]** 넷째 단계는 내부 토의입니다. 팀장, 직무전문가, QA, 매니저가 모여 원인과 개선안을 이야기합니다. 통제 가능한 원인은 BPO가 무엇을 바꿀지, 통제 불가한 원인은 고객사에 무엇을 요청할지 정합니다.
8. **[보고 및 건의 → 개선점 보고]** 다섯째 단계는 보고 및 건의입니다. DSAT는 원인에 BPO가 정한 개선점을 붙여 고객사에 보고합니다. 이번 건은 바뀐 절차를 팀 전체에 다시 교육하고 이해도를 확인했다고 보고합니다.
9. **[보고 및 건의 → 인사이트 공유]** CSAT도 같은 다섯 단계를 거칩니다. 고객이 왜 만족했는지를 모아, 고객사의 제품과 서비스가 잘하고 있는 점을 알려 주는 인사이트로 공유합니다.
10. **[보고 및 건의 → 해결 또는 건의]** 미해결·방치 케이스는 티켓 상태를 같은 L1·L2로 나누고, SLA와 품질(Quality)에 미치는 영향을 함께 봅니다. 해결책이 없는 케이스가 쌓이면 상담사들이 비슷한 문의에 잘못 안내해 DSAT가 늘고 처리도 늦어지기 때문입니다. BPO 안에서 풀 수 있으면 직접 해결하고, 고객사의 허락이 필요하면 프로세스를 만들어 건의합니다.
11. **[전체]** 🟦 지민의 티켓 몇 건에서는 고객에게 확인 질문을 여러 번 되풀이하는 흐름도 보였습니다. 이런 흐름은 QA 점수만으로는 잘 보이지 않습니다. 다음 1:1 코칭의 근거가 되고, 코칭으로도 나아지지 않을 때는 PIP의 근거가 됩니다.

**확인 문제 1.** 상담사들이 반품 절차를 서로 다르게 알고 안내해서 생긴 DSAT입니다. L1·L2는 어떻게 분류할까요?
- a. L1 Customer, L2 통제 불가.
- b. L1 Support, L2 통제 가능. ✅
- c. L1 Process, L2 통제 불가.
- 해설: 상담사의 응대 태도나 제품·절차 지식의 차이는 L1 Support입니다. 교육으로 BPO가 직접 메울 수 있으니 L2는 통제 가능입니다.

**확인 문제 2.** 고객 답변을 기다리며 2주째 열려 있는 티켓들이 SLA를 끌어내리고 있습니다. 이 티켓들을 종료하려면 고객사의 허락이 필요합니다. 어떻게 할까요?
- a. SLA가 더 떨어지기 전에, 팀에서 오늘 바로 모두 종료 처리한다.
- b. 고객 답변을 기다리는 건이니 그대로 두고, SLA 하락 사유로 보고만 한다.
- c. 팔로업 횟수를 정해 종료하는 프로세스를 고객사에 건의한다. ✅
- 해설: 고객사의 허락이 필요한 해결은 BPO가 프로세스를 만들어 건의합니다. 승인되면 기준이 생겨, 같은 티켓이 다시 쌓이지 않습니다.

**다음으로:** 스크러빙에서 보인 흐름은 팀원과 마주 앉을 근거가 됩니다. 다음은 1:1 코칭입니다.

## 용어집 (새 용어 3개)

| 용어 | 이름 | 뜻 |
|---|---|---|
| Scrubbing | 스크러빙 | 처리된 티켓과 미해결 티켓을 다시 읽고 원인을 찾아 L1·L2로 분류하는 점검입니다. 우선순위는 DSAT, CSAT, 미해결·방치 케이스 순이며, 결과는 고객사 보고와 팀 코칭에 쓰입니다. |
| RCA | 원인 분석 (Root Cause Analysis) | 겉으로 드러난 문제 뒤의 진짜 원인을 찾는 분석입니다. 같은 문제가 되풀이되지 않게 하려면 증상이 아니라 원인을 고쳐야 합니다. |
| Backlog | 백로그 (미해결 잔량) | 해결되지 않고 쌓여 있는 케이스입니다. 오래 방치되면 응답이 늦어지고, SLA와 평균 해결 시간 같은 지표가 왜곡됩니다. |
