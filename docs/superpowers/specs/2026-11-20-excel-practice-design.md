# 학습 앱 3단계 — 미소의 엑셀 연습 설계

작성일: 2026-11-20 · 상태: 검토 중

## 1. 목적

신입 팀장이 꼭 갖춰야 할 엑셀 능력 11가지를, 미소와 함께 휴대폰에서 **타자 없이** 카드와 칸을 눌러서만 익힌다. 1단계에서 "리아의 텃밭" 자리에 넣기로 한 부분이다. 참고: Fullcharge13/Learning-SQL의 레슨 흐름(설명 카드 → 문제 → 요약)과 "카드 조립 → 실제 실행 → 결과 비교" 채점. 그 저장소의 글·그림·이름은 쓰지 않고 방식만 참고한다.

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
- 11개 레슨, 1번부터 차례로 연다. 레슨마다 설명 카드 2~3장, 문제 6개(객관식 2, 빈칸 2, 조립 2), 세 줄 요약.
- 수식 조립은 예시 표에서 실제로 계산해 결과 값으로 채점한다.
- 오프라인, 아래 메뉴, 한국어/영어가 다른 주제와 같다.

**하지 않을 것 (이번 단계)**
- 실제 엑셀 파일 만들기·내려받기, 자유 입력, 차트, 매크로.
- 엑셀 문제를 "오늘의 연습"에 섞기, 엑셀 전용 배지 (나중에 따로).
- XP·엽전·상점·의상 (Learning-SQL에 있지만 우리는 뺀다).

**실패로 볼 것**
- 맞는 수식인데 순서가 달라 오답 처리되는 것.
- 업무와 동떨어진 예제. 모든 예제는 컨택센터 일.
- 휴대폰에서 표가 넘쳐 옆으로 밀리는 것.

## 3. 사용자가 정한 것
- 타이핑 없이 노드(카드·칸) 선택만으로. Learning-SQL 참고.
- 기능 11개 모두: ① 셀 주소와 범위 ② SUM·AVERAGE·MIN·MAX ③ 비율과 ROUND ④ COUNTIF·COUNTIFS ⑤ SUMIFS·AVERAGEIFS ⑥ IF ⑦ XLOOKUP(또는 VLOOKUP) ⑧ 시간 계산(초 → 분:초) ⑨ 정렬·필터 ⑩ 피벗 테이블 ⑪ 조건부 서식.
- 레슨당 6문제 (B).
- 채점: 우리 함수만 계산하는 작은 계산기 (A).

## 4. 방법 비교 (선택: A)
| | 방법 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A** | 작은 계산기 직접 | 결과가 같으면 정답, 결과 값과 쓰인 칸을 보여 줌, 테스트가 정답·헷갈림 카드를 실제 계산으로 확인 | 만드는 일이 가장 많음 |
| B | 카드 순서 비교 | 단순 | 다른 순서의 맞는 답이 오답, 결과 값 없음 |
| C | 공개 라이브러리 | — | HyperFormula는 GPL(우리는 MIT), 다른 것은 크고 빌드 도구 필요 |

## 5. 동작

### 5.1 예시 표 (모든 레슨 공통, 화면에 "예시" 표시)
"미소 팀 하루 콜 기록" 한 장. 상담사 8명(2~9행), 1행은 머리글.

| 열 | 내용 | 예 |
|---|---|---|
| A | 상담사 ID | S01 |
| B | 이름 | 가상의 한국 이름 |
| C | 팀 | A팀 / B팀 |
| D | 콜 수 | 정수 |
| E | 총 처리 시간(초) | 정수 |
| F | 30초 안에 받은 콜 | 정수 (서비스 레벨용) |
| G | 목표 콜 수 | 정수 |

- 정확한 값은 문안 작업에서 정하되, 각 문제의 정답이 헷갈림 카드의 결과와 겹치지 않게 고른다 (예: 합계와 평균이 우연히 같지 않게).
- 휴대폰에서 7열이 한 화면에 들어가게 좁은 글꼴·짧은 머리글. 넘치면 표 안에서만 옆으로 밀린다.

### 5.2 문제 종류
| 종류 | 하는 일 | 채점 |
|---|---|---|
| choice | 보기 3개 중 고르기 | 정답 번호 |
| blank | 수식의 빈칸 하나를 칩 3개 중에서 채우기 | 채운 수식을 계산해 정답 값과 비교 (수식이 아닌 빈칸은 정답 번호) |
| build | 섞인 카드를 눌러 수식 완성 (누르면 줄로 올라가고, 줄에서 누르면 빠짐) | 계산 결과 = 정답 값. 계산 오류·빈 줄은 오답 |
| cell | 표에서 칸이나 범위를 눌러 고르기 (레슨 ①) | 고른 칸 = 정답 칸 |
| steps | 메뉴 단계 카드를 순서대로 누르기 (레슨 ⑨⑩⑪) | 순서 비교. 문안에서 [순서 무관]으로 묶은 단계끼리는 순서를 바꿔도 정답 |

- 문제 구성 (제작자 결정): 모든 레슨이 객관식 2, 빈칸 2, "손으로 만드는 문제" 2. 손으로 만드는 문제는 레슨 ②~⑧은 build, 레슨 ①은 cell, 레슨 ⑨⑩⑪은 steps.
- 조립 카드 수: 정답 카드 + 헷갈림 카드 1~3장, 합계 10장 이하.
- 정답이면 결과 값과 계산에 쓰인 칸을 표에서 강조한다. steps는 맞히면 바뀐 표(정렬·필터·색칠·피벗 요약)를 보여 준다.
- 틀리면 해설과 "다시 해 보기". 다시 해서 맞혀도 되고, 그냥 다음 문제로 넘어가도 된다. 레슨은 6문제를 다 보면 마침.
- 점수 (제작자 결정): 처음 시도에서 맞힌 문제 수(0~6). 레슨을 다시 하면 더 높은 점수를 남긴다. 레슨 끝과 레슨 목록에 "6개 중 5개"처럼 보여 준다.

### 5.3 계산기가 다루는 것
- 숫자, 글자("A팀", ">=100", 빈 글자 ""), TRUE·FALSE, 칸(`D2`, `$D$2`), 범위(`D2:D9`), + − × ÷, 비교(`>`, `>=`, `<`, `<=`, `=`, `<>`), `&`(이어 붙이기).
- 함수: SUM, AVERAGE, MIN, MAX, COUNT, ROUND, COUNTIF, COUNTIFS, SUMIF, SUMIFS, AVERAGEIFS, IF, XLOOKUP, VLOOKUP, INT, MOD, TEXT(형식 `"0%"`, `"0.0%"`, `"m:ss"`만).
- 조건 글자: `"A팀"`, `">=100"`, `"<>B팀"` 형태. 와일드카드는 다루지 않는다.
- 결과 비교: 숫자는 1e-9 이내, 글자는 정확히 같게.
- 이 밖의 것은 계산 오류로 오답. 화면에는 "이 연습에서 다루지 않는 수식이에요"가 아니라 일반 오답 해설.

│ ┌ 예시 표 (줄인 모습) ─────────────┐ │
│ │ A   B     C    D   …             │ │

## 6. 문안
- 제작자가 문안을 쓰고, 한국어 문안(예시 표 값, 설명 카드, 66문제, 해설, 요약, 화면 문구)은 따로 `docs/superpowers/specs/2026-11-20-excel-practice-copy.md`에 쓰고 **세 묶음**(레슨 1~4, 5~8, 9~11)으로 나눠 확정받는다 (제작자 결정: 한 번에 66문제는 검토가 무겁다). 다 확정되면 영어를 붙여 보여 준다. 만들기는 문안이 모두 확정된 뒤 시작한다.
- 문안 문서는 레슨마다 같은 틀(설명 카드 → 문제 1~6: 종류·질문·보기/칩/카드·정답·결과 값·해설 → 요약 3줄)로 써서 테스트가 읽을 수 있게 한다. 구현 계획은 문안이 모두 확정된 뒤 쓴다.
- 지켜야 할 규칙: 숫자에는 "예시", 캡션·정의 3문장 이하, "센터마다", AHT = 평균 처리 시간, 서비스 레벨 정의는 Codex·용어집과 같게, "진상" 금지, 함수 이름은 영어 그대로.

## 8. 고치는 곳과 확인
- 새 폴더 `excel/` (index.html, 계산기, 표, 레슨 데이터, 그리기, 앱, css). 고치는 곳: `home/` (배우기 카드, 내 학습), `shared/appbar.js`, `sw.js` 재생성, README, LOG 18, 참고 자료(Learning-SQL 방식 참고 표기).
- 테스트: 계산기(함수마다, 칸·범위·$, 조건 글자, 오류), 모든 레슨의 조립 정답을 계산해 정답 값과 같은지, 헷갈림 카드 하나를 넣거나 정답 카드 하나를 빼면 오답이 되는지, blank 칩 셋 중 정답만 맞는지, 카드 10장 이하, 문안 = 확정 문서, 영어에 한글 없음, 진도 저장 막힘·깨짐, 레슨 차례 열림.
- 브라우저 점검: 320/390px에서 표·카드 넘침 없음, 어두운 화면, 오프라인, 첫 레슨 끝까지.
