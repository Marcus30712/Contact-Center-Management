공통 원칙: 스텝은 3문장 이내로 씁니다. 출처 없는 숫자에는 "예시"를 붙입니다. 시점은 "당신 = 막 팀장이 된 사람"입니다.

## 레슨 1. 팀장이 된 첫날

| 항목 | 한국어 |
|---|---|
| 제목 | 팀장이 된 첫날 |
| 짧은 이름 | 첫날 |
| 부제 | 운영하기 전에, 무엇을 어떤 순서로 파악할지 정합니다. |
| 노드 | 팀원 파악 · 개인 성과 · 팀의 기여 · 첫 계획 |

스텝:

1. 이 레슨의 목적은 팀장이 된 첫날, 팀을 운영하기 전에 무엇을 어떤 순서로 파악할지 정하는 것입니다. 이 강의 전체가 이 순서를 따라갑니다.
2. 당신은 오늘부터 15명(예시) 팀의 팀장입니다. 팀원들은 당신을 모르고, 당신도 팀원들이 어떻게 일해 왔는지 모릅니다.
3. 첫 단계는 팀원 파악입니다. 누가 있고, 각자 어떤 스킬을 가지고 어떤 업무를 해 왔는지 알아야 합니다. 레슨 2의 로스터가 그 출발점입니다.
4. 둘째 단계는 개인 성과입니다. 지민, 서준, 준호가 지금까지 어떤 숫자를 냈고 실제로 어떻게 일해 왔는지 봅니다. 레슨 3과 4에서 다룹니다.
5. 셋째 단계는 팀의 기여입니다. 이 팀이 프로젝트 전체에서 어떤 몫을 해 왔는지, 어디가 우수했고 어디가 모자랐는지 봅니다. 레슨 5에서 다룹니다.
6. 넷째 단계는 첫 계획입니다. 팀원 한 명씩 어떻게 도울지 정하고, 부매니저에게 운영 방침을 받아 팀 전체의 계획을 세웁니다. 레슨 6과 7에서 다룹니다.
7. 혼자 파악하지 않습니다. 팀을 가장 가까이에서 봐 온 직무전문가 하린, QA 도현, 트레이너 유나의 기록과 관찰이 큰 도움이 됩니다.
8. 첫 몇 주 동안은 큰 변화를 서두르지 않습니다. 파악하기 전에 바꾸면 잘 돌아가던 것까지 흔들 수 있습니다.
9. 첫날에는 팀원들에게 짧게 인사하고, 앞으로 몇 주 동안 한 사람씩 이야기를 나누겠다고 알립니다. 팀원들도 새 팀장이 무엇을 할지 궁금해합니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 첫날, 전 팀장 때와 다른 방식이 눈에 띕니다. 어떻게 할까요? |
| 보기 a (오답) | 첫날 허들에서 내 방식을 알리고 바로 바꾼다. 처음에 기준을 세워야 나중에 덜 흔들린다. |
| a 피드백 | 이유를 알기 전에 바꾸면 잘 돌아가던 것까지 흔들리고, 팀원들은 새 팀장을 경계합니다. |
| 보기 b (정답) | 그 방식에도 사정이 있을 수 있으니, 적어 두고 이유를 파악한 뒤에 바꿀지 정한다. |
| 보기 c (오답) | 팀이 오래 해 온 방식이니, 팀원들이 불편하지 않게 앞으로도 손대지 않는다. |
| c 피드백 | 파악한 뒤에도 바꾸지 않으면 개선할 기회를 놓칩니다. 바꿀지는 파악한 다음에 정합니다. |
| 해설 | 첫 몇 주는 바꾸기보다 파악하는 시간입니다. |
| 2번 질문 | 팀을 파악하는 순서로 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 개인 성과 → 팀원 파악 → 팀의 기여 → 첫 계획 |
| a 피드백 | 숫자를 먼저 보면 그 숫자 뒤의 사람과 사정을 놓칩니다. |
| 보기 b (정답) | 팀원 파악 → 개인 성과 → 팀의 기여 → 첫 계획 |
| 보기 c (오답) | 팀의 기여 → 팀원 파악 → 개인 성과 → 첫 계획 |
| c 피드백 | 팀 전체부터 보면 한 사람 한 사람이 가려지고, 기여의 원인도 보이지 않습니다. |
| 해설 | 사람을 먼저 알고, 성과와 기여를 본 뒤에 계획합니다. |
| 다음 레슨 연결 | 파악의 출발점은 팀원 한 사람 한 사람입니다. 먼저 로스터를 만듭니다. |

## 레슨 2. 로스터 만들기

| 항목 | 한국어 |
|---|---|
| 제목 | 로스터 만들기 |
| 짧은 이름 | 로스터 |
| 부제 | 팀원마다 무엇을 할 수 있고 무엇을 해 왔는지 한곳에 모읍니다. |
| 노드 | 기본 정보 · 스킬과 업무 · 근무 형태 · 계속 고치기 |

스텝:

1. 이 레슨의 목적은 팀원 한 사람 한 사람의 정보를 로스터 한 장에 모아, 팀을 한눈에 보는 것입니다.
2. 첫 단계는 기본 정보입니다. 이름, 입사일, 정식 팀 합류일, 교육 기수를 적습니다. 서준처럼 합류한 지 얼마 안 된 사람과 지민처럼 2년째인 사람은 도울 방식이 다릅니다.
3. 둘째 단계는 스킬과 업무입니다. 처리할 수 있는 채널과 문의 유형, 맡아 온 일을 적습니다. 예를 들어 준호는 선임으로 신입 버디와 어려운 케이스 검토를 맡아 왔습니다.
4. 기록만으로 모르는 것은 사람에게 묻습니다. 직무전문가 하린은 누가 어떤 유형에서 막히는지, 트레이너 유나는 누가 어떤 교육을 받았는지 알고 있습니다.
5. 셋째 단계는 근무 형태입니다. 근무 시간대, 정해진 휴가, 파트타임 여부를 적습니다. 인력 계획과 코칭 일정을 짤 때 필요합니다.
6. 로스터에는 사실만 적습니다. "성실함"처럼 인상을 적으면 나중에 다른 사람이 볼 때 근거가 없습니다.
7. 개인 정보는 필요한 만큼만 정해진 곳에 둡니다. 로스터는 팀장과 꼭 필요한 사람만 봅니다.
8. 넷째 단계는 계속 고치기입니다. 로스터는 첫 주에 한 번 만들고 끝나는 문서가 아닙니다. 새 스킬을 배우거나 업무가 바뀌면 그때마다 고칩니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 로스터의 "스킬" 칸에 알맞은 것은 무엇일까요? |
| 보기 a (오답) | "열정적이고 성실함, 팀원들과 잘 어울리며 늘 먼저 돕는 편" |
| a 피드백 | 성격에 대한 인상은 어떤 일을 맡길 수 있는지 알려 주지 않습니다. |
| 보기 b (정답) | "채팅·이메일, 환불·배송 문의, 신입 버디 경험" |
| 보기 c (오답) | "지난달 CSAT 팀 3위" |
| c 피드백 | 순위는 성과 기록에 둡니다. 스킬 칸은 할 수 있는 일을 적는 곳입니다. |
| 해설 | 스킬은 할 수 있는 채널, 문의 유형, 맡아 본 일로 적습니다. |
| 2번 질문 | 기록에는 없지만 서준이 어떤 유형에서 자주 막히는지 알고 싶습니다. 누구에게 묻는 것이 알맞을까요? |
| 보기 a (오답) | 같은 팀 상담사들에게 서준이 요즘 어디서 힘들어하는지 슬쩍 물어본다. |
| a 피드백 | 동료에게 다른 사람을 평가하게 하면 팀 안에 불편한 분위기가 생깁니다. |
| 보기 b (정답) | 서준을 매일 도와 온 직무전문가 하린에게 묻는다. |
| 보기 c (오답) | 묻지 않고 숫자에 나타날 때까지 기다린다. |
| c 피드백 | 숫자에 나타날 때쯤이면 서준은 이미 오래 막혀 있었을 수 있습니다. |
| 해설 | 상담사가 어디서 막히는지는 매일 도와 온 직무전문가가 가장 잘 압니다. |
| 다음 레슨 연결 | 로스터로 누가 있는지 알았습니다. 이제 각자 어떤 성과를 내 왔는지 볼 차례입니다. |

## 레슨 3. 개인 성과 확인

| 항목 | 한국어 |
|---|---|
| 제목 | 개인 성과 확인 |
| 짧은 이름 | 개인 성과 |
| 부제 | 최근 몇 달의 기록으로 숫자가 어떻게 움직여 왔는지 봅니다. |
| 노드 | 기록 모으기 · 추세 보기 · 함께 읽기 · 메모하기 |

스텝:

1. 이 레슨의 목적은 팀원마다 최근 기록을 모아, 숫자가 어떻게 움직여 왔는지 보는 것입니다. 한 달의 점수보다 몇 달의 흐름이 더 많은 것을 알려 줍니다.
2. 첫 단계는 기록 모으기입니다. 최근 6개월(예시)의 티켓 처리 건수, 평균 처리 시간(AHT), 고객 만족도(CSAT), 품질 점수를 팀원별로 모읍니다.
3. 둘째 단계는 추세 보기입니다. 숫자가 꾸준한지, 오르는지, 떨어지는지 봅니다. 지민의 CSAT가 석 달째(예시) 내려가고 있다면, 그 시작 시점에 무슨 일이 있었는지가 단서입니다.
4. 숫자 하나만 보지 않습니다. 처리 건수가 많은데 품질 점수가 낮다면 서두르고 있을 수 있고, 처리 시간이 긴데 CSAT가 높다면 꼼꼼하게 응대하고 있을 수 있습니다.
5. 셋째 단계는 함께 읽기입니다. QA 도현에게 품질 점수가 왜 그렇게 나왔는지, 자주 감점된 항목이 무엇인지 듣습니다. 점수의 이유는 점수를 매긴 사람이 가장 잘 압니다.
6. 직무전문가 하린에게는 스크러빙에서 본 상담사별 트렌드를 받습니다. 같은 실수가 반복되는 사람과 다른 사람을 잘 돕는 사람이 보입니다.
7. 넷째 단계는 메모하기입니다. 팀원마다 잘하는 점, 보완할 점, 확인할 질문을 한두 줄씩 적어 둡니다. 이 메모가 레슨 6의 출발점이 됩니다.
8. 이 단계에서는 결론을 내리지 않습니다. 숫자는 질문을 만들 뿐이고, 답은 실제로 일하는 모습을 보고 나서 찾습니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 준호의 처리 건수는 팀에서 가장 많은데 품질 점수는 평균보다 낮습니다. 먼저 할 일은 무엇일까요? |
| 보기 a (오답) | 처리 건수가 많으니 우수 사원으로 적어 둔다. |
| a 피드백 | 한 숫자만 보면 품질이 떨어지는 이유를 놓칩니다. |
| 보기 b (정답) | QA에게 감점 항목을 듣고, 녹취로 확인할 질문을 적는다. |
| 보기 c (오답) | 품질 점수가 낮으니 바로 코칭 대상으로 정한다. |
| c 피드백 | 이유를 모른 채 코칭하면 엉뚱한 곳을 고치게 됩니다. |
| 해설 | 숫자끼리 어긋나면 결론을 내리기보다 이유를 확인할 질문을 만듭니다. |
| 2번 질문 | 팀원 성과를 볼 기간으로 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 지난주 한 주 |
| a 피드백 | 한 주는 우연히 좋거나 나쁠 수 있어 흐름이 보이지 않습니다. |
| 보기 b (정답) | 최근 몇 달 (예시: 6개월) |
| 보기 c (오답) | 입사 뒤 전체 기간 (길게 볼수록 정확하므로) |
| c 피드백 | 오래된 기록이 섞이면 지금의 모습이 흐려집니다. |
| 해설 | 최근 몇 달의 흐름을 봐야 지금의 모습과 변화가 함께 보입니다. |
| 다음 레슨 연결 | 숫자가 질문을 만들었습니다. 이제 숫자 뒤에서 실제로 어떻게 일하는지 직접 확인합니다. |

## 레슨 4. 녹취와 티켓 직접 보기

| 항목 | 한국어 |
|---|---|
| 제목 | 녹취와 티켓 직접 보기 |
| 짧은 이름 | 직접 보기 |
| 부제 | 숫자 뒤에서 실제로 어떻게 일하는지 확인합니다. |
| 노드 | 고르기 · 듣고 읽기 · 습관 찾기 · 원인 확인 |

스텝:

1. 이 레슨의 목적은 녹취와 티켓을 직접 보며, 팀원마다 실제로 어떻게 일하는지 확인하는 것입니다.
2. 첫 단계는 고르기입니다. 팀원마다 몇 건씩(예시: 3~5건) 고르되, 잘 끝난 건과 불만으로 끝난 건을 섞습니다. 레슨 3의 메모에 적은 질문과 관련된 건을 먼저 고릅니다.
3. 둘째 단계는 듣고 읽기입니다. 인사, 문제 파악, 안내, 마무리의 흐름을 따라가며 무엇을 잘했고 어디서 흔들렸는지 적습니다.
4. 준호의 콜을 들어 보니, 문제를 빨리 해결하지만 고객이 이해했는지 확인하지 않고 끝냅니다. 처리 건수는 많고 품질 점수는 낮았던 이유가 보입니다.
5. 셋째 단계는 습관 찾기입니다. 한 건의 실수가 아니라 여러 건에서 반복되는 모습을 찾습니다. 좋은 습관도 똑같이 적습니다.
6. QA 도현과 같은 건을 함께 들어 보면 좋습니다. 같은 콜을 두고 무엇을 보는지 맞추면, 나중에 코칭할 때 기준이 어긋나지 않습니다.
7. 넷째 단계는 원인 확인입니다. 찾은 습관이 그 사람만의 습관인지, 교육에서 그렇게 배웠기 때문인지 트레이너 유나에게 확인합니다.
8. 교육 내용이 원인이라면 한 사람을 코칭할 일이 아니라 교육을 고칠 일입니다. 트레이너와 함께 다음 교육에 반영합니다.

## 레슨 5. 팀의 기여 파악

| 항목 | 한국어 |
|---|---|
| 제목 | 팀의 기여 파악 |
| 짧은 이름 | 팀의 기여 |
| 부제 | 프로젝트 전체에서 이 팀이 해 온 몫과 강점, 약점을 정리합니다. |
| 노드 | 목표와 결과 · 다른 팀과 비교 · 강점과 약점 · 한 장 요약 |

스텝:

1. 이 레슨의 목적은 이 팀이 프로젝트 전체에서 어떤 몫을 해 왔는지, 어디가 우수했고 어디가 모자랐는지 정리하는 것입니다.
2. 첫 단계는 목표와 결과입니다. 프로젝트가 이 팀에 기대한 목표(스케줄 준수율, 품질, 처리량)와 지난 몇 달의 실제 결과를 나란히 놓습니다.
3. 둘째 단계는 다른 팀과 비교입니다. 같은 프로젝트의 다른 팀과 비교하면, 우리 팀만의 문제인지 프로젝트 전체의 문제인지 구분됩니다.
4. 비교는 순위를 매기기 위한 것이 아닙니다. 다른 팀이 잘하는 방식에서 배울 점을 찾기 위해서입니다.
5. 셋째 단계는 강점과 약점입니다. 예를 들어 "채팅 품질은 프로젝트 1위(예시), 스케줄 준수율은 목표 미달"처럼 구체적으로 적습니다.
6. 원인을 함께 봅니다. 직무전문가 하린의 스크러빙과 VOC 기록에서 고객 불만의 주제를, QA 도현의 기록에서 팀 공통 감점 항목을 확인합니다.
7. 팀이 바꿀 수 있는 것과 바꿀 수 없는 것을 나눕니다. 정책이나 시스템 때문이라면 팀의 약점이 아니라 위로 올려야 할 문제입니다.
8. 넷째 단계는 한 장 요약입니다. 팀의 목표, 결과, 강점, 약점, 원인을 한 장에 정리합니다. 이 요약을 들고 레슨 7에서 부매니저를 만납니다.

## 레슨 6. 팀원 한 명씩 다루는 법 정하기

| 항목 | 한국어 |
|---|---|
| 제목 | 팀원 한 명씩 다루는 법 정하기 |
| 짧은 이름 | 한 명씩 |
| 부제 | 첫 1:1 면담으로 듣고, 팀원마다 도울 방법을 메모합니다. |
| 노드 | 첫 면담 · 듣기 · 맞춰 보기 · 개인 메모 |

스텝:

1. 이 레슨의 목적은 팀원 한 사람씩 짧은 첫 면담을 하고, 지금까지 파악한 것과 합쳐 각자를 어떻게 도울지 정하는 것입니다.
2. 첫 단계는 첫 면담입니다. 팀원마다 15분(예시) 정도 1:1 시간을 잡습니다. 평가가 아니라 서로 알아 가는 자리라고 먼저 말합니다.
3. 둘째 단계는 듣기입니다. 본인이 생각하는 강점, 어려운 점, 앞으로 해 보고 싶은 일을 묻습니다. 기록으로는 알 수 없는 것이 여기서 나옵니다.
4. 지민은 최근 집안 사정으로 야간 근무가 힘들다고 말합니다. CSAT가 떨어지기 시작한 시점과 겹칩니다. 숫자의 이유가 사람에게서 나옵니다.
5. 개인 사정은 필요한 만큼만 듣고, 지민의 허락 없이 다른 사람에게 말하지 않습니다. 근무 조정이 필요하면 정해진 절차로 진행합니다.
6. 셋째 단계는 맞춰 보기입니다. 본인의 이야기와 기록, 직접 본 모습을 맞춰 봅니다. 서로 다르면 어느 쪽이 맞는지 단정하지 않고 더 지켜봅니다.
7. 넷째 단계는 개인 메모입니다. 팀원마다 강점, 도울 점, 맡겨 볼 일, 다음에 확인할 날을 적습니다. 예를 들어 준호는 마무리 확인 습관이 잡힐 때까지 신입 버디 역할을 잠시 쉬고, 그 습관을 함께 봅니다.
8. 메모는 계획이지 낙인이 아닙니다. 몇 주 뒤 다시 보며 맞지 않는 부분은 고칩니다.

## 레슨 7. 부매니저·매니저에게 방침 받기

| 항목 | 한국어 |
|---|---|
| 제목 | 부매니저·매니저에게 방침 받기 |
| 짧은 이름 | 방침 받기 |
| 부제 | 파악한 것을 들고 운영 방침을 받고, 첫 계획을 세웁니다. |
| 노드 | 보고 준비 · 방침 듣기 · 첫 계획 · 팀에 알리기 |

스텝:

1. 이 레슨의 목적은 지금까지 파악한 내용을 부매니저(AM)나 매니저(OM)에게 보고하고, 운영 방침을 받아 팀의 첫 계획을 세우는 것입니다.
2. 첫 단계는 보고 준비입니다. 레슨 5의 팀 요약과 레슨 6의 개인 메모에서 꼭 전할 것만 추립니다. 팀원의 개인 사정은 보고에 넣지 않습니다.
3. 민석 부매니저와의 첫 미팅은 30분(예시)입니다. 팀의 지금 모습, 그 원인, 당신이 보는 우선순위를 짧게 전합니다.
4. 둘째 단계는 방침 듣기입니다. 프로젝트가 이번 분기에 가장 중요하게 보는 지표, 팀에 기대하는 것, 팀장이 정할 수 있는 범위를 확인합니다.
5. 당신의 우선순위와 방침이 다르면 근거를 들어 의견을 말합니다. 그래도 방침이 정해지면 그 방침을 따르고, 의견은 기록해 둡니다.
6. 셋째 단계는 첫 계획입니다. 방침에 맞춰 앞으로 한 달(예시) 동안 할 일을 정합니다. 누구를 어떻게 코칭할지, 팀 전체에서 무엇을 먼저 바꿀지, 직무전문가·QA·트레이너에게 무엇을 부탁할지 적습니다.
7. 계획은 작게 시작합니다. 한 번에 다 바꾸려 하면 팀도 당신도 지칩니다. 가장 큰 문제 한두 개부터 시작합니다.
8. 넷째 단계는 팀에 알리기입니다. 팀 허들에서 앞으로의 방향과 첫 목표를 짧게 전합니다. 누구의 이름도 지적하지 않고, 팀이 함께 갈 방향만 말합니다.
9. 한 달(예시) 뒤 결과를 들고 민석 부매니저와 다시 만납니다. 파악과 계획, 실행과 점검이 이 순서로 계속 돕니다.
