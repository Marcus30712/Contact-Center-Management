# 직급 선택과 SME 강의 — 설계 문서

작성일: 2026-11-25 · 상태: 승인됨 (2026-11-25)

## 1. 의도와 이유

큐크래프트는 지금까지 **신입 팀장**만을 위한 앱이었다. 앞으로는 처음 그 자리를 맡는 사람이 직급마다 미리 공부할 수 있게 넓힌다. 대상은 신입으로 입사하는 상담사, 그리고 SME·팀장·부매니저·매니저로 승진하는 사람이다(사용자, 2026-11-25).

직급 콘텐츠는 하나씩 채운다(사용자 선택 A). 첫 직급은 **SME**다. 이미 있는 재료(Codex의 SME 정보, 에스컬레이션·캘리브레이션·스크러빙·육성 SOP)를 가장 많이 다시 쓸 수 있어서, 직급 선택 구조를 빨리 검증할 수 있다.

**새 SME가 가장 어려워하는 것** (사용자의 현장 경험):
- 상담사에서 처음 진급해, 플로어에서 혹은 온라인으로 **8~15명**을 서포트한다.
- 서포트 대상이 서로 다르다. 교육 중인 상담사, 방금 교육을 마친 상담사, 기존 상담사, **동료였던 선임 상담사**, 그리고 **팀장**까지 받쳐야 한다.
- SME는 평가하는 자리가 아니라 **에스컬레이션을 승인하는 자리**다. 그래서 동료였던 선임도 친분과 상관없이 SME에게 승인과 도움을 요청한다. 새 SME는 이 관계를 처음부터 직급에 맞게 잡아야 한다.
- 팀장 서포트에는 세 가지가 있다. 인원이 많거나 팀장이 자리에 없을 때 **출석 관리 대행**, 코칭에 쓸 **스크러빙 상담 트렌드 요약**을 팀장에게 전달하기, 고객사가 내려보낸 업데이트를 전하는 **허들 진행**.
- **스크러빙은 SME의 주된 일**이다. 매일 3~4건 정도 하며, 팀에 지식을 돌려주고 트렌드를 파악하는 데 쓴다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 사용자가 자기 직급을 고르고, 설정에서 언제든 바꿀 수 있다. 직급은 다섯 가지다: 상담사, SME, 팀장, 부매니저, 매니저.
- 고른 직급의 강의가 홈 "배우기"의 맨 위에 온다. 다른 강의도 막지 않는다. 새 SME도 팀장 콘텐츠를 미리 볼 수 있어야 한다.
- Codex 커리어 매트릭스와 직무별 일일 업무가 고른 직급 화면으로 열린다.
- 새 강의 **"SME 첫걸음"**(가칭)을 7개 레슨으로 만든다. 시점은 "당신 = 막 진급한 SME"다.
- 레슨 진도, 오늘의 연습, 배지는 직급이 바뀌어도 그대로 이어진다.

**비목표**
- 상담사·부매니저·매니저 강의. 이 직급들은 "준비 중"으로만 표시한다.
- SME용 상황별 길잡이. 길잡이는 팀장용으로 그대로 둔다.
- 기존 라이프사이클·SOP 레슨의 시점을 바꾸는 것.
- 직급에 따라 콘텐츠를 숨기거나 잠그는 것.
- 일반/기술지원 트랙. SME 강의는 트랙을 나누지 않는다. 채널마다 다른 점은 본문에 짧게 적는다.

**반목표**
- 직급을 고르지 않으면 앱을 쓸 수 없게 만드는 것. 고르지 않으면 지금처럼 팀장으로 동작한다.
- 직급을 바꾸면 기록이 지워지거나 갈라지는 것.
- SME에게 상담사를 평가하거나 징계할 권한이 있는 것처럼 쓰는 것. SME는 **승인하고 돕는** 자리다.
- 출처 없는 숫자를 기준처럼 쓰는 것. "8~15명", "하루 3~4건"은 사용자의 현장 경험에서 나온 **예시**로 표시하고, 센터마다 다를 수 있다고 적는다.
- 동료였던 선임을 문제 인물처럼 그리는 어조.

## 3. 접근 방식

| 방법 | 내용 | 결정 |
|---|---|---|
| A. 새 강의 폴더 + 직급 저장, 홈에서 순서만 바꿈 | SOP 라이브러리처럼 `sme/` 폴더를 만들고 같은 레슨 엔진을 쓴다. 직급은 기기에 저장하고, 홈·Codex·시작 문구가 이 값을 읽는다 | **사용자 선택** — 검증된 SOP 라이브러리 방식을 따르고, 다음 직급을 붙이기 쉽고, 승진해도 기록이 이어진다 |
| B. 기존 강의 안에 직급 전환 버튼 | 라이프사이클 트랙 전환처럼 "팀장/SME"를 넣는다 | SME 7개 주제가 라이프사이클 6단계와 맞지 않고, 직급이 늘수록 레슨 하나에 문장이 너무 많아진다 |
| C. 직급마다 앱을 따로 | 직급별 사이트 | 용어집·엑셀·설정이 복사본으로 갈라지고, 승진하면 기록이 끊긴다 |

## 4. 무엇이 바뀌나

### 4.1 직급 저장
- 저장 키: `queuecraft:role`. 값: `agent` · `sme` · `tl` · `am` · `om` (Codex `daily.js`·`career.js`의 id와 같다).
- 값이 없거나 이상하면 `tl`로 본다. 지금 쓰는 사람의 화면은 바뀌지 않는다.
- 설정의 **기록 백업**에 포함한다(언어·화면 설정처럼). **학습 초기화**로는 지우지 않는다. 직급은 학습 기록이 아니라 설정이기 때문이다.

### 4.2 직급 고르기
- **처음 고르기**: 직급이 저장되어 있지 않으면 홈에서 한 번 "어떤 자리를 준비하나요?"라고 묻는다. 다섯 직급 버튼과 "나중에 고를게요"가 있다. "나중에"를 누르면 팀장으로 두고 다시 묻지 않는다(이 사실을 저장한다). 이미 쓰던 사람에게도 한 번 묻는다.
- **바꾸기**: 설정에 "내 직급" 칸을 더한다. 언어 칸과 같은 모양의 다섯 개 선택지다.
- 아직 강의가 없는 직급(상담사·부매니저·매니저)도 고를 수 있다. 고르면 홈에 "이 직급 강의는 준비 중이에요. 그동안 볼 만한 곳"이라는 안내와 Codex 커리어·일일 업무 링크를 보여 준다.

### 4.3 홈 화면
- "배우기" 카드에 SME 강의 카드를 더한다.
- 카드 순서: 내 직급 강의를 맨 위에 둔다. SME를 고르면 SME 강의 → 라이프사이클 → SOP → 엑셀 순서다. 팀장을 고르면 지금 순서와 같다.
- 김미소 소개 문구 "신입 팀장을 돕는 선배 매니저"를 모든 직급에 맞는 문구로 바꾼다(문안 단계에서 확정).
- "내 학습 · 이어서"는 내 직급 강의에서 먼저 찾는다.

### 4.4 시작 화면
- 소개 문구 "신입 팀장을 위한 컨택센터 운영 배우기"를 직급 중립 문구로 바꾼다(문안 단계에서 확정). 시간대별 인사는 그대로 둔다. 대부분 직급과 상관없는 내용이다. 팀장에게만 맞는 문장이 있으면 문안 단계에서 고친다.

### 4.5 Codex 원페이저
- 커리어 매트릭스: 운영팀에서 "나" 표시와 처음 열리는 칸을 저장된 직급으로 정한다(지금은 `CAREER.you.level = 'tl'` 고정).
- 직무별 일일 업무: 처음 열리는 직급을 저장된 직급으로 정한다(지금은 `DAILY.defaultRole = 'tl'` 고정).
- "내 한 주 돌아보기"는 팀장용이라 팀장 화면에만 그대로 둔다.
- 5대 핵심팀 화면은 바꾸지 않는다(모든 직급이 운영팀이다).

### 4.6 SME 강의 (새 폴더 `sme/`)
- 형식은 SOP 라이브러리와 같다: 번호 목록 첫 화면, 레슨마다 다이어그램, 한 스텝씩 넘기기, 레슨 끝 판단 문제 2개, 다음 레슨 연결 카드.
- 진도 키: `sme-course:v1`. 오늘의 연습 문제 풀, 기록 백업, 학습 초기화에 모두 포함한다.
- 시점: "당신 = 막 진급한 SME". 고정 인물은 다른 강의와 이어지게 정한다. 예를 들어 상담사 한지민을 기존 상담사로 다시 등장시킨다. 이름과 인물은 문안 단계에서 확정한다.
- 레슨 구성 (사용자 확인, 2026-11-25):
  1. **SME가 된 첫날** — 역할, 하루 일과, 내가 승인할 일과 팀장에게 넘길 일 (Codex SME 정보 활용)
  2. **교육 중·막 교육을 마친 상담사 서포트** — 네스팅 기간에 옆에서 붙어 있기
  3. **기존 상담사 서포트** — 에스컬레이션을 받아 승인하거나 처리하기
  4. **동료였던 선임 서포트** — 친분이 아니라 직급으로 승인하고 돕기
  5. **팀장 서포트** — 출석 관리 대행, 스크러빙 상담 트렌드 요약 전달, 고객사 업데이트 허들 진행
  6. **요청이 동시에 몰릴 때** — 플로어와 온라인 요청의 우선순위
  7. **팀에 지식 돌려주기** — 매일 하는 스크러빙(예시: 하루 3~4건), VOC, 캘리브레이션
- 각 레슨 끝에서 관련된 기존 SOP·Codex로 이어지는 링크를 건다(예: 3 → SOP 에스컬레이션, 7 → SOP 스크러빙·캘리브레이션).

### 4.7 그 밖에
- 용어집: 새로 필요한 용어가 생기면 더한다(예: 버디, 허들). 문안 단계에서 정한다.
- README 표, `home/data.js`, `sw.js`(`python3 tools/sw_list.py`로 다시 만들기), LOG.md를 갱신한다.

## 6. 완성 기준

- 처음 연 사람에게 직급 질문이 한 번 나오고, 고르면 홈 순서와 Codex 기본 화면이 바뀐다.
- 직급을 고르지 않거나 "나중에"를 누르면 지금과 똑같이 팀장으로 동작한다.
- 설정에서 직급을 바꿔도 모든 진도와 배지가 그대로 있다. 백업 파일에 직급이 들어가고, 학습 초기화 뒤에도 직급은 남는다.
- SME 레슨 7개를 끝까지 넘길 수 있고, 마친 레슨의 문제가 오늘의 연습에 나온다.
- 저장이 막힌 브라우저에서도 앱이 동작한다(팀장으로).
- 전체 테스트(`agent-lifecycle`에서 `npm test`)가 통과한다.

## 7. 빌더에게 맡기는 것 (제안한 결정)

- 직급 질문은 별도 화면이 아니라 홈 위에 뜨는 작은 시트로 한다. 설정의 "홈 화면 추가" 시트와 같은 방식이다.
- 직급 질문과 첫 실행 투어가 겹치면 직급 질문을 먼저 보여 준다.
- "나중에 고를게요"를 눌렀다는 사실은 `queuecraft:role-asked`에 저장한다. 직급 질문은 홈 주소로 들어왔을 때만 띄운다. 다른 페이지로 바로 들어온 경우에는 띄우지 않는다.
- 직급 값을 읽고 쓰는 작은 모듈을 `shared/role.js`에 둔다. 홈·설정·Codex가 이 모듈을 함께 쓴다.
- 레슨 다이어그램 모양, 레슨 파일 구조, 테스트 배치는 기존 SOP 라이브러리를 따른다.
