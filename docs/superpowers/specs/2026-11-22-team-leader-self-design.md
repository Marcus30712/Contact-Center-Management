# 팀장 자신의 시간·코칭 품질·동료에서 팀장으로 — 설계 문서

작성일: 2026-11-22 · 상태: 승인됨 (2026-11-22)

## 1. 의도와 이유

글로벌 고객센터 운영 조사(보고서 「글로벌 고객센터 운영과 큐크래프트 보완점」 H3)에서 나온 보완점이다. 큐크래프트는 팀장이 **하는 절차**는 가르치지만, 팀장이 그 절차에 **시간을 실제로 쓰는지**, 코칭이 **제대로 된 코칭인지**, 그리고 어제까지 동료였던 사람들의 **팀장이 되는 전환**은 다루지 않는다.

근거(원리만 쓰고 숫자는 옮기지 않는다):
- 팀장이 코칭에 쓰는 시간은 생각보다 적고, 우선순위 낮은 일에 시간을 빼앗긴다(Gartner, 2024).
- 새 관리자의 흔한 실수는 기술보다 관계 문제다: 전 동료 편애, 상의 없는 절차 변경, 관찰 없이 물려받은 지시 실행, 실수 인정 거부(ICMI, 2023).
- 숫자 하나만 겨냥한 코칭은 몰입을 해치고, 선도 센터는 관리자가 팀장의 코칭을 관찰해 코치를 코칭한다(McKinsey, 2018 — 오래된 자료라 원리만).

## 2. 목표 · 비목표 · 반목표

**목표**
- 1:1 코칭에 세 가지를 보강한다: 세션 뒤의 코치 관찰(새 스텝), 숫자 하나만 보고 코칭하지 않기(체크포인트 문제), 코칭과 피드백·준수 점검의 구분(용어집 정의).
- Codex '직무별 일일 업무'의 팀장 항목에 "내 한 주 돌아보기" 체크리스트를 붙인다.
- 새 SOP "동료에서 팀장으로"(첫 90일)를 '팀장이 직접 하는 절차' 묶음 끝에 더한다. 체크포인트 2문제.
- 상황별 길잡이에 "함께 일하던 동료들의 팀장이 됐다"를 더해 새 SOP → 팀장 일과로 잇는다.

**비목표**
- 팀장 시간 기록·계산 기능, 저장되는 체크리스트(체크는 화면에서만, 새로고침하면 지워진다).
- 새 트랙, 새 섹션, Codex 새 장.
- 리더십 이론 강의(상황 대응 리더십 등)나 외부 표준 인용.

**반목표**
- 조사 자료의 숫자(코칭 시간 비율, 팀원 수 비율 등)를 기준처럼 보이게 쓰는 것. 기간·시간은 모두 "예시".
- 새 팀장을 탓하거나 겁주는 어조. 함정은 "흔히 생기는 일"로 쓴다.
- 특정 국가의 법, "진상", 3문장을 넘는 캡션.

## 3. 접근 방식

| 방법 | 내용 | 결정 |
|---|---|---|
| A. 기존 자리 보강 + 새 SOP 하나 | 코칭 SOP 보강, 팀장 일과 체크리스트, 전환 SOP, 길잡이 상황 | **사용자 선택** — 익숙한 형식이고 길잡이 규칙(기존 콘텐츠로만 연결)과 맞는다 |
| B. 팀장 전용 Codex 새 장 | 세 주제를 한 장에 | Codex 원문의 해당 장을 확인할 수 없어, 원문 없이 Codex를 새로 쓰는 셈 |
| C. 코칭 SOP·원페이저만 보강 | 가장 작음 | 새 팀장의 관계 함정이 빠짐 |

## 4. 무엇이 바뀌나

**① 1:1 코칭 SOP (`sop-library/lessons/02-coaching.js`)**
- 다섯 단계는 그대로 둔다(Codex 원문 보존). 레슨 스텝 한도가 12개라(지금 11개) 새 스텝은 하나만 넣는다(사용자 선택 A).
- 마무리 뒤에 다이어그램 옆 노드 "코치 관찰"(세션 뒤의 일)을 더하고 스텝 하나로 설명한다. 다섯 단계 본류와 구분되게 옆에 둔다(설계자 판단).
- "숫자 하나만 보고 코칭하지 않기"는 체크포인트 3번 문제(데이터 준비)로 다룬다.
- "코칭과 피드백·준수 점검의 구분"은 용어집 '1:1 코칭' 정의에 한 문장을 더해 다룬다(`glossary/terms.js`, 3문장 이내).

**② Codex 팀장 일과 (`codex/data/daily.js`, 렌더)**
- 팀장 역할을 고르면 업무표 아래에 "내 한 주 돌아보기" 체크리스트(5항목)가 보인다. 누를 수 있는 체크 상자지만 저장하지 않는다(페이지 안에서 다른 곳을 눌러도 유지, 새로고침하면 지워짐).
- Codex 원문이 아니므로 Codex 데이터·확정 문안 파일에 넣지 않고 별도 데이터로 두며, 화면에 "큐크래프트가 덧붙인 항목"이라고 밝힌다(설계자 판단).

**③ 새 SOP "동료에서 팀장으로" (`sop-library/lessons/10-transition.js`)**
- 묶음: 팀장이 직접 하는 절차, 순서: 캘리브레이션 다음(6번). 여러 팀이 함께 하는 절차는 7~10번으로 밀린다.
- 세 단계: 듣기(예시: 첫 30일) → 기준 합의(예시: 31~60일) → 실행과 점검(예시: 61~90일), 90일 돌아보기는 부매니저와 함께(다이어그램 옆 노드). 사례 인물은 새 팀장이 가장 친했던 동료 하은(Haeun, `personaName`); 새 팀장은 '당신'.
- '90일'은 이 절차의 틀(제목·부제)이라 "예시"를 붙이지 않고, 단계별 기간에만 붙인다(설계자 판단). 신규 프로젝트 론칭의 마지막 연결 문구("SOP 아홉 가지")를 "열 가지"로 고친다.
- 연결: 캘리브레이션 → 동료에서 팀장으로 → 신규 입사자 온보딩. 캘리브레이션의 연결 문구를 고친다.
- 홈 카드·SOP 목록의 절차 수(9 → 10)와 이름 목록을 고친다.

**④ 상황별 길잡이 (`guide/data.js`)**
- s18 "함께 일하던 동료들의 팀장이 됐다": 먼저 볼 곳 = 새 SOP, 이어서 볼 곳 = Codex 팀장 일과(`#daily-tl`). 묶음은 '조직과 일하는 법' 쪽(`org`)에 둔다(설계자 판단).

## 5. 문안

한국어 초안은 `2026-11-22-team-leader-self-copy.md`. 사용자 승인 전에는 구현하지 않는다. 승인 뒤 영어를 같은 형식의 `.en.md`로 쓰고, 문안 문서와 화면이 같은지 테스트로 확인한다. 고치는 기존 문구(코칭 SOP, 캘리브레이션·론칭 연결 문구, 홈 카드)는 예전 확정 문서를 고치지 않고 이 문안 문서가 담는다(스크러빙·육성 SOP와 같은 방식).

## 6. 성공 확인

- 기존 SOP·길잡이 테스트(순서, 연결, 다이어그램 도형, 예시 표시, 금지어, 문장 수)를 새 내용이 통과한다.
- 새 SOP가 목록·홈 카드·연결·오늘의 연습 문제에 들어간다. 길잡이 s18의 링크가 실제 레슨·원페이저를 연다.
- 체크리스트는 키보드로 체크할 수 있고 저장되지 않는다. 브라우저 점검: 320·1280px, 한국어·영어 넘침 없음.
