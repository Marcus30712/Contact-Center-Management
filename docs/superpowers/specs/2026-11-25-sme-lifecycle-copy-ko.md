# 서포트 라이프사이클 — 한국어 문안 초안

작성일: 2026-11-25 · 상태: 승인됨 (2026-11-25, 레슨 1·2에 사용자가 알려 준 현장 방식 반영) · 설계: `2026-11-25-sme-learn-set-design.md` §4.2

공통 원칙: 스텝은 3문장 이내로 씁니다. 출처 없는 숫자에는 "예시"를 붙입니다. 시점은 "당신 = SME"입니다.

SME 첫걸음과 겹치지 않게 하는 방법: SME 첫걸음은 SME가 된 직후의 적응(역할, 승인 범위, 관계, 대행 업무)을 다룹니다. 이 강의는 상담사 한 사람(서준)이 자라는 순서를 따라가며 **단계마다 SME가 확인하고, 기록하고, 넘기는 것**과 **다음 단계로 넘어가는 신호**를 다룹니다. 같은 장면이 필요한 곳에서는 SME 첫걸음의 레슨을 가리키고 반복하지 않습니다.

## 레슨 1. 교육 중인 상담사 지원

| 항목 | 한국어 |
|---|---|
| 제목 | 교육 중인 상담사 지원 |
| 짧은 이름 | 교육 중 |
| 부제 | 가르치는 사람은 트레이너, SME는 현장을 보여 줍니다. |
| 노드 | 역할 나누기 · 시연과 쉐도잉 · 관찰 기록 · 인계 준비 |

스텝:

1. 이 레슨의 목적은 교육 중인 상담사를 지원할 때 SME가 무엇을 확인하고, 무엇을 기록하고, 언제 넘기는지 아는 것입니다. 이 강의는 서준 한 사람이 자라는 순서를 따라 단계마다 SME의 절차를 봅니다.
2. 서준은 입사 3주 차(예시) 교육생입니다. 이론 교육을 마치고 이번 주부터 OJT로 실제 문의를 처음 받습니다.
3. 첫 단계는 역할 나누기입니다. 교육 과정과 수료 판단은 트레이너가 맡습니다. SME는 실제 시스템과 도구로 교육 내용이 현장에서 어떻게 쓰이는지 보여 줍니다.
4. OJT 시작 전에 트레이너와 짧게 맞춥니다. 이번 주에 서준이 받을 채널과 문의 유형, SME가 참관할 시간을 정합니다.
5. 둘째 단계는 시연과 쉐도잉입니다. 실제 시스템과 도구로 여러 유형의 티켓을 처리하는 모습을 시연합니다. 멀티 헤드셋을 연결해 SME가 받는 실제 콜을 서준이 함께 듣게 합니다.
6. 서준이 직접 콜을 받기 시작하면 반대로 SME가 멀티 헤드셋으로 함께 듣습니다. 서준이 막히면 통화를 잠시 음소거하고 다음 절차를 알려 줍니다.
7. 교육 자료와 현장 방식이 다르면 서준에게 따로 고쳐 가르치지 않고 트레이너에게 먼저 전합니다. 교육생은 두 사람에게서 다른 답을 들으면 무엇을 따라야 할지 혼란스러워합니다.
8. 셋째 단계는 관찰 기록입니다. 참관이 끝날 때마다 서준이 혼자 처리한 유형, 도움이 필요했던 유형, 자주 멈춘 지점을 짧게 적습니다.
9. 기록은 평가가 아니라 인계 자료입니다. 점수나 성격이 아니라 어떤 문의에서 어떤 행동이 나왔는지만 적습니다.
10. 넷째 단계는 인계 준비입니다. 수료 일주일 전(예시)에 트레이너와 기록을 함께 보고, 네스팅에서 더 가까이 볼 문의 유형을 정합니다.
11. 수료 여부를 정하는 것은 트레이너와 팀장입니다. SME는 기록을 근거로 의견을 전합니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | OJT 중 서준이 교육 자료대로 응대했는데, 실제로는 현장에서 쓰지 않는 절차였습니다. 어떻게 할까요? |
| 보기 a (오답) | 교육 자료는 신경 쓰지 말고 현장 방식대로 하라고 서준에게 말한다. |
| a 피드백 | 서준은 트레이너와 SME에게서 다른 답을 듣게 되고, 교육 자료도 그대로 남아 다음 교육생이 같은 혼란을 겪습니다. |
| 보기 b (정답) | 이번 문의는 함께 바르게 마무리하고, 다른 부분을 트레이너에게 전해 교육 내용을 맞춘다. |
| 보기 c (오답) | 교육 중이니 틀려도 그대로 둔다. |
| c 피드백 | 고객은 상대가 교육생인지 모릅니다. 실제 문의는 바르게 마무리해야 합니다. |
| 해설 | 현장과 교육이 다르면 교육생이 아니라 트레이너와 맞춥니다. 그래야 다음 교육생도 같은 답을 듣습니다. |
| 2번 질문 | 서준의 OJT 관찰 기록으로 알맞은 것은 무엇일까요? |
| 보기 a (오답) | "자신감이 부족함" |
| a 피드백 | 성격에 대한 인상은 네스팅에서 무엇을 도와야 할지 알려 주지 않습니다. |
| 보기 b (정답) | "환불 문의에서 본인 확인 다음 단계를 매번 물어봄" |
| 보기 c (오답) | "OJT 점수 70점(예시)" |
| c 피드백 | 점수를 매기는 것은 트레이너와 QA의 일이고, 숫자만으로는 어떤 문의를 도와야 할지 알 수 없습니다. |
| 해설 | 관찰 기록은 문의 유형과 행동으로 씁니다. 네스팅에서 어디를 도울지 정하는 인계 자료가 됩니다. |
| 다음 레슨 연결 | 서준이 교육을 수료했습니다. 이제 트레이너의 손을 떠나 SME 곁에서 실제 문의를 받는 네스팅입니다. |

## 레슨 2. 교육을 마친 상담사 지원 (네스팅)

| 항목 | 한국어 |
|---|---|
| 제목 | 교육을 마친 상담사 지원 |
| 짧은 이름 | 네스팅 |
| 부제 | 가까이 붙었다가, 정해 둔 기준에 따라 조금씩 떨어집니다. |
| 노드 | 인계받기 · 지원 간격 정하기 · 지원 줄여 가기 · 졸업 점검 |

스텝:

1. 이 레슨의 목적은 네스팅 기간에 지원을 얼마나 가까이 시작해 언제 줄일지, 그리고 정식 팀으로 넘기는 기준을 아는 것입니다. 옆에서 돕는 방법은 SME 첫걸음 레슨 2에서 다뤘습니다.
2. 서준이 교육을 수료했습니다. 앞으로 2주(예시) 동안 네스팅 그룹에서 실제 문의를 받습니다.
3. 첫 단계는 인계받기입니다. 트레이너에게 OJT 관찰 기록을 받고, 서준이 아직 혼자 받아 보지 않은 문의 유형을 확인합니다. 네스팅 동안 그 유형들을 고루 경험하게 합니다.
4. 둘째 단계는 지원 간격 정하기입니다. 첫 주(예시)에는 정해진 간격으로 먼저 다가가고, 어려운 유형은 보내기 전에 함께 봅니다. 간격과 함께 볼 유형은 수진 팀장과 미리 맞춥니다.
5. 매일 끝에 세 가지를 짧게 적습니다. 혼자 끝낸 유형, 도움을 받은 유형, 에스컬레이션한 건입니다.
6. 셋째 단계는 지원 줄여 가기입니다. 한 유형을 며칠 연속(예시) 혼자 끝내면, 그 유형은 먼저 확인하지 않고 요청이 올 때만 봅니다.
7. 지원은 한꺼번에 끊지 않고 유형별로 줄입니다. 옆에서 직접 돕는 대신 채팅으로 필요한 정책 문서 링크를 보내, 서준이 스스로 찾아 처리하게 합니다. 갑자기 혼자 남으면 신입은 묻기를 더 망설입니다.
8. 무엇이 바뀌는지 서준에게 미리 말합니다. "이제 배송 문의는 혼자 해도 돼요. 막히면 언제든 불러요."라고 하면 떨어지는 것이 버려지는 것이 아니라 인정받는 것으로 들립니다.
9. 넷째 단계는 졸업 점검입니다. 네스팅이 끝나기 전에 기록을 수진 팀장과 함께 보고, 정식 팀으로 넘길지 네스팅을 늘릴지 정합니다. 결정은 팀장이 합니다.
10. 정식 팀으로 넘어갈 때는 아직 자주 막히는 유형을 함께 넘깁니다. 다른 팀으로 가면 그 팀의 SME와 팀장에게, 같은 팀에 남으면 내 기록에 표시해 둡니다.

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 서준이 배송 문의를 사흘 연속(예시) 혼자 끝냈습니다. 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 오늘부터 모든 지원을 멈춘다. |
| a 피드백 | 한 유형이 익숙해졌다고 다른 유형까지 준비된 것은 아닙니다. 지원은 유형별로 줄입니다. |
| 보기 b (정답) | 배송 문의는 요청이 올 때만 보기로 하고, 그렇게 바뀐다고 서준에게 알려 준다. |
| 보기 c (오답) | 아직 네스팅 기간이니 모든 문의를 계속 먼저 확인한다. |
| c 피드백 | 혼자 할 수 있는 것까지 계속 확인하면 서준은 스스로 판단할 기회를 잃고, 다른 신입을 도울 시간도 줄어듭니다. |
| 해설 | 기준에 닿은 유형부터 하나씩 지원을 줄이고, 바뀌는 것을 미리 말합니다. |
| 2번 질문 | 네스팅 마지막 주인데 서준이 환불 문의에서 계속 막힙니다. 어떻게 할까요? |
| 보기 a (오답) | 기간이 끝났으니 정식 팀으로 넘긴다. |
| a 피드백 | 막히는 유형을 그대로 두고 넘기면 정식 팀에서 고객과 서준이 함께 힘들어집니다. |
| 보기 b (정답) | 환불 문의 기록을 수진 팀장에게 보여 주고, 네스팅 연장이나 추가 교육을 상의한다. |
| 보기 c (오답) | 앞으로 환불 문의는 SME가 대신 처리하겠다고 한다. |
| c 피드백 | 대신 처리해 주면 서준은 그 유형을 끝내 배우지 못하고, SME의 하루도 막힙니다. |
| 해설 | 넘길지 늘릴지는 팀장이 정합니다. SME는 막히는 유형을 기록으로 보여 줍니다. |
| 다음 레슨 연결 | 서준이 정식 팀에 합류했습니다. 이제 SME가 먼저 다가가는 대신, 서준이 필요할 때 찾아오는 관계로 바뀝니다. |

## 레슨 3. 정식 상담사 지원

| 항목 | 한국어 |
|---|---|
| 제목 | 정식 상담사 지원 |
| 짧은 이름 | 정식 |
| 부제 | 요청이 오면 돕고, 요청으로 오지 않는 것은 스크러빙으로 찾습니다. |
| 노드 | 요청으로 받기 · 스크러빙으로 보기 · 다시 가까이 · 성장 신호 전하기 |

스텝:

1. 이 레슨의 목적은 혼자 일하게 된 상담사를 요청과 스크러빙으로 지원하고, 다시 가까이 붙어야 할 때와 다음 자리를 준비할 때를 아는 것입니다.
2. 정식 팀에 합류하고 석 달(예시)이 지났습니다. 서준은 이제 대부분의 문의를 혼자 처리합니다.
3. 첫 단계는 요청으로 받기입니다. 서준은 승인이 필요하거나 막힐 때 플로어나 메신저로 SME를 부릅니다. 승인하고 처리하는 순서는 SME 첫걸음 레슨 3과 같습니다.
4. 둘째 단계는 스크러빙으로 보기입니다. 혼자 일하는 상담사의 실수는 스스로 모르기 때문에 요청으로 오지 않습니다. 매일 하는 스크러빙에서 서준의 티켓이 나오면 반복되는 모습이 있는지 봅니다.
5. 찾은 것은 행동과 티켓 번호로 적어 둡니다. 한 번의 실수는 서준에게 짧게 알려 주고, 반복되면 팀장에게 건네는 요약에 담습니다.
6. 셋째 단계는 다시 가까이 붙기입니다. 새 상품이 나오거나 정책이 바뀌면 정식 상담사도 그 유형에서는 다시 신입이 됩니다. 바뀐 뒤 첫 며칠(예시)은 관련 문의를 먼저 확인합니다.
7. 서준의 품질이 갑자기 떨어지거나 요청이 크게 늘어도 다시 가까이 갑니다. 이유가 업무 밖에 있어 보이면 캐묻지 않고 팀장에게 알립니다.
8. 넷째 단계는 성장 신호 전하기입니다. 서준이 어려운 문의를 혼자 끝내고, 다른 상담사의 질문에 답하기 시작하면 기록해 둡니다.
9. 이런 신호는 팀장에게 전합니다. 신입의 버디를 맡길지, 선임으로 키울지는 팀장이 정합니다.

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 스크러빙에서 서준의 티켓 세 건(예시)에 같은 확인 단계 누락이 보였습니다. 어떻게 할까요? |
| 보기 a (오답) | 서준이 요청하지 않았으니 그대로 둔다. |
| a 피드백 | 혼자 일하는 상담사의 실수는 스스로 모르기 때문에 요청으로 오지 않습니다. |
| 보기 b (정답) | 티켓 번호와 함께 팀장에게 건넬 요약에 담는다. |
| 보기 c (오답) | 팀 채팅방에 서준의 티켓을 사례로 올린다. |
| c 피드백 | 이름이 드러나면 서준은 창피를 당하고, 팀은 실수를 숨기기 시작합니다. |
| 해설 | 반복되는 모습은 행동과 사례로 팀장에게 전합니다. 한 번의 실수는 서준에게 짧게 알려 줍니다. |
| 2번 질문 | 다음 주에 새 요금제가 출시됩니다. 정식 상담사 서준에게 알맞은 지원은 무엇일까요? |
| 보기 a (오답) | 정식 상담사이니 허들 공지만으로 충분하다. |
| a 피드백 | 처음 보는 문의는 경력과 상관없이 막힙니다. 공지만으로는 첫 며칠의 실수를 막기 어렵습니다. |
| 보기 b (정답) | 출시 후 첫 며칠은 새 요금제 문의를 먼저 확인한다. |
| 보기 c (오답) | 새 요금제 문의는 당분간 SME가 모두 받는다. |
| c 피드백 | SME 혼자 받으면 고객 대기가 길어지고, 서준은 새 요금제를 배우지 못합니다. |
| 해설 | 새것이 나오면 정식 상담사도 그 유형만큼은 다시 신입처럼 가까이 지원합니다. |
| 다음 레슨 연결 | 서준처럼 자란 상담사는 언젠가 선임이 됩니다. 이 팀에는 이미 선임이 된 준호가 있습니다. |

## 레슨 4. 선임 상담사 지원

| 항목 | 한국어 |
|---|---|
| 제목 | 선임 상담사 지원 |
| 짧은 이름 | 선임 |
| 부제 | 기준을 나누고, 일을 맡기고, 다음 자리를 준비시킵니다. |
| 노드 | 기준 공유 · 일 나누기 · 판단 확인 · 다음 자리 준비 |

스텝:

1. 이 레슨의 목적은 선임 상담사와 승인 기준을 나누고, 신입 지원을 함께 맡으며, 다음 자리를 준비하도록 돕는 것입니다. 동기였던 선임과의 관계는 SME 첫걸음 레슨 4에서 다뤘습니다.
2. 준호는 팀의 선임 상담사입니다. 서준이 네스팅을 할 때 버디로 옆에서 도왔습니다.
3. 첫 단계는 기준 공유입니다. 내 승인 기준과 자주 오는 에스컬레이션 사례를 준호와 함께 봅니다. 기준이 바뀌면 준호에게도 먼저 알립니다.
4. 선임이 기준을 알면 다른 상담사의 일반 질문에 SME와 같은 답을 줄 수 있습니다. 승인은 여전히 SME나 팀장이 합니다.
5. 둘째 단계는 일 나누기입니다. 신입의 버디, 일반 질문 1차 답변, 어려운 케이스 함께 검토처럼 준호가 맡을 수 있는 일을 정합니다. 맡기는 범위는 팀장과 먼저 맞춥니다.
6. 셋째 단계는 판단 확인입니다. 선임의 에스컬레이션은 답을 몰라서보다 판단을 확인받고 싶어서 올 때가 많습니다. 준호의 판단을 먼저 듣고, 기준에 맞으면 그대로 승인합니다.
7. 판단이 기준과 다르면 어느 부분이 다른지 짚어 줍니다. 이유를 알면 준호는 다음에 같은 판단을 혼자 할 수 있습니다.
8. 넷째 단계는 다음 자리 준비입니다. 준호가 SME나 팀장 자리를 바란다면 허들 진행이나 캘리브레이션 참관처럼 그 자리의 일을 조금씩 맡겨 봅니다.
9. 맡긴 일과 결과를 기록해 팀장에게 전합니다. 승진은 팀장과 매니저가 정하고, SME의 기록은 그 근거가 됩니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 일반 질문을 맡은 준호가 승인이 필요한 보상 요청까지 "괜찮을 거야"라며 처리해 주려 합니다. 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 준호는 기준을 알고 있으니 그대로 둔다. |
| a 피드백 | 기준을 아는 것과 승인할 권한은 다릅니다. 선임이 승인하기 시작하면 승인 기록이 남지 않습니다. |
| 보기 b (정답) | 일반 질문은 계속 준호에게 맡기고, 승인이 필요한 건은 SME에게 넘기도록 다시 맞춘다. |
| 보기 c (오답) | 앞으로 준호에게 질문 답변을 맡기지 않는다. |
| c 피드백 | 한 건 때문에 나눈 일을 모두 거두면 SME에게 다시 일이 몰리고, 준호도 자랄 기회를 잃습니다. |
| 해설 | 선임에게 나누는 것은 답변과 지원이고, 승인은 SME와 팀장에게 남깁니다. |
| 2번 질문 | 준호가 에스컬레이션을 보내며 해결 방법을 적어 두었고, 그 방법은 기준에 맞습니다. 어떻게 할까요? |
| 보기 a (오답) | 처음부터 다시 판단해 내 방법을 찾는다. |
| a 피드백 | 기준에 맞는 판단을 다시 하면 고객 응대가 늦어지고, 준호는 자기 판단을 믿지 않게 됩니다. |
| 보기 b (정답) | 준호의 방법대로 승인하고, 판단이 맞았다고 짧게 알려 준다. |
| 보기 c (오답) | 선임이니 앞으로는 확인 없이 알아서 처리하라고 한다. |
| c 피드백 | 승인 권한은 사람이 아니라 자리에 붙어 있습니다. 확인 없이 처리하면 기록과 책임이 흐려집니다. |
| 해설 | 선임의 판단이 기준에 맞으면 그대로 승인하고 알려 줍니다. 이것이 선임을 다음 자리로 키우는 방법입니다. |
| 다음 레슨 연결 | 교육생부터 선임까지 한 바퀴를 돌았습니다. 마지막은 이 모든 단계를 함께 보는 사람, 팀장입니다. |

## 레슨 5. 팀장 지원

| 항목 | 한국어 |
|---|---|
| 제목 | 팀장 지원 |
| 짧은 이름 | 팀장 지원 |
| 부제 | 단계마다 본 것을 팀장에게 모으고, 다시 처음으로 돌아갑니다. |
| 노드 | 단계 현황 · 대행 범위 · 넘기는 기준 · 다시 처음으로 |

스텝:

1. 이 레슨의 목적은 앞의 네 단계에서 본 것을 팀장에게 모아, 팀장이 사람마다 다음 단계를 정하도록 돕는 것입니다. 출석 관리, 트렌드 요약, 허들 같은 대행 업무는 SME 첫걸음 레슨 5에서 다뤘습니다.
2. 수진 팀장은 매주 월요일(예시) 팀원마다 다음 단계를 정합니다. 누구를 네스팅에서 정식 팀으로 넘길지, 누구에게 버디를 맡길지 같은 결정입니다.
3. 첫 단계는 단계 현황 정리입니다. 팀원마다 지금 어느 단계인지, 지난주에 본 것, 다음 단계로 갈 신호가 있는지를 한 줄씩 적습니다.
4. 예를 들어 "서준: 정식 석 달 차, 새 요금제 문의 안정, 다른 상담사 질문에 답하기 시작"처럼 씁니다. 수진 팀장은 이 한 줄로 서준에게 다음 기수의 버디를 맡길지 정할 수 있습니다.
5. 둘째 단계는 대행 범위 맞추기입니다. SME가 대신 하는 일과 하지 않는 일을 분기마다(예시) 수진 팀장과 다시 확인합니다. 팀 인원이나 정책이 바뀌면 범위도 바뀝니다.
6. 셋째 단계는 넘기는 기준입니다. 근태, 성과 조치, 개인 사정, 정책 밖 승인은 단계와 상관없이 팀장에게 넘깁니다. 넘길 때는 있었던 일을 사실대로 적어 함께 보냅니다.
7. 넘긴 건은 결과도 물어 기록해 둡니다. 같은 일이 다시 생기면 어떻게 할지 알게 됩니다.
8. 넷째 단계는 다시 처음으로입니다. 새 교육 기수가 들어오면 SME의 지원은 다시 교육 중 단계에서 시작합니다. 지난 기수의 기록은 트레이너와 함께 보며 다음 기수를 준비하는 데 씁니다.
9. 한 바퀴를 돌 때마다 팀의 기록이 쌓이고, 같은 곳에서 막히는 사람이 줄어듭니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 수진 팀장이 월요일 회의 전에 팀원 현황을 부탁했습니다. 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 지난주에 문제가 있었던 팀원만 골라 보낸다. |
| a 피드백 | 잘하고 있는 팀원의 성장 신호가 빠지면, 팀장은 누구를 다음 단계로 키울지 정할 수 없습니다. |
| 보기 b (정답) | 팀원마다 지금 단계, 지난주에 본 것, 다음 단계 신호를 한 줄씩 적어 보낸다. |
| 보기 c (오답) | 지난주 하루 일과를 시간대별로 길게 적어 보낸다. |
| c 피드백 | 팀장이 결정에 필요한 것은 사람별 단계와 신호입니다. 긴 일지에서는 그것을 찾기 어렵습니다. |
| 해설 | 단계 현황은 사람마다 한 줄로, 다음 결정을 내릴 수 있게 씁니다. |
| 2번 질문 | 정식 상담사 한 명의 결근이 늘고, 업무 요청도 갑자기 많아졌습니다. 어떻게 할까요? |
| 보기 a (오답) | SME가 직접 이유를 묻고 근무 시간을 조정해 준다. |
| a 피드백 | 근태와 개인 사정은 팀장이 맡습니다. SME가 조정하면 같은 상황의 다른 팀원과 기준이 달라집니다. |
| 보기 b (정답) | 늘어난 업무 요청은 다시 가까이 지원하고, 결근과 변화는 사실대로 적어 팀장에게 넘긴다. |
| 보기 c (오답) | 정식 상담사이니 지켜보기만 한다. |
| c 피드백 | 변화를 알고도 넘기지 않으면 팀장은 문제가 커진 뒤에야 알게 됩니다. |
| 해설 | 업무 지원은 SME가, 근태와 개인 사정은 팀장이 맡습니다. 둘을 나눠 처리합니다. |
| 마지막 연결 | 서포트 라이프사이클을 마쳤습니다. 에스컬레이션 승인, 스크러빙 같은 절차는 SME SOP 라이브러리에서 하나씩 자세히 다룰 예정입니다. |
