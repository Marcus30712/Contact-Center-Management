# 부매니저 SOP 라이브러리 — 한국어 문안 초안

작성일: 2026-11-28 · 상태: 승인 (2026-11-28) · 바탕: 부매니저 첫걸음(`2026-11-28-am-course-design.md`)의 역할 경계, 상담사·직무전문가 SOP 라이브러리의 형식

공통 원칙: 스텝은 3문장 이내로 씁니다. 출처 없는 숫자에는 "예시"를 붙입니다. 민석을 따라가는 3인칭이며, 레슨마다 마지막 스텝은 미소의 "그때 알았더라면" 한마디입니다.

다른 강의와 겹치지 않게 하는 방법:
- 부매니저 첫걸음은 역할이 바뀌는 첫 몇 달의 판단을 다룹니다. 이 강의는 **매주·매달 되풀이되는 절차를 순서대로** 다룹니다. 무엇을, 언제까지, 누구에게, 어떻게 남기는지가 중심입니다.
- 팀장·직무전문가 SOP와 이어지는 절차는 부매니저가 맡는 부분만 다루고, 한 줄로 앞뒤를 이어 줍니다.

## 레슨 1. 팀장 주간 성과 미팅

| 항목 | 한국어 |
|---|---|
| 제목 | 팀장 주간 성과 미팅 |
| 짧은 이름 | 주간 미팅 |
| 부제 | 매주 같은 순서로 지표를 보고, 조치와 담당을 남깁니다. |
| 누가 | 팀장 → 부매니저 → 매니저 |
| 노드 | 자료 받기 · 미팅 진행 · 조치 정하기 · 매니저 보고 |

스텝:

1. 이 절차의 목적은 매주 같은 순서로 세 마켓의 지표를 보고, 누가 무엇을 언제까지 할지 남기는 것입니다.
2. 첫 단계는 자료 받기입니다. 민석은 미팅 전날 오후(예시)까지 마켓마다 같은 양식의 지표 요약을 받습니다. 응대율, 평균 처리 시간, 품질 점수, 근태와 지난주 조치의 결과가 한 장에 들어갑니다.
3. 둘째 단계는 미팅 진행입니다. 팀장마다 5분(예시)씩 지난주 결과, 이번 주 계획, 도움이 필요한 일을 말합니다. 민석은 목표에서 벗어난 숫자만 골라 질문합니다.
4. 셋째 단계는 조치 정하기입니다. 문제마다 할 일, 담당, 기한을 하나씩 정하고 미팅 기록에 적습니다. 담당이 정해지지 않은 조치는 다음 주에 그대로 남아 있습니다.
5. 신임 팀장인 태오가 "품질을 신경 쓰겠다"고만 말하면, 민석은 무엇을 언제까지 할지로 바꿔 묻습니다. 예를 들어 "이번 주 안에 상담사 3명(예시)과 1:1 코칭"처럼 확인할 수 있게 적습니다.
6. 넷째 단계는 매니저 보고입니다. 미팅이 끝난 날 정은 매니저에게 마켓별 요약, 새 조치, 매니저의 판단이 필요한 일을 보냅니다.
7. 다음 미팅은 지난주 조치 목록을 확인하는 것으로 시작합니다. 끝난 것, 늦어진 것, 이유를 먼저 보고 새 숫자로 넘어갑니다.
8. 미소의 한마디: 미팅을 잘 마쳤다고 생각했는데, 다음 주에 보니 아무도 안 움직였던 적이 있어요. 담당과 기한을 적지 않은 조치는 조치가 아니더라고요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 주간 미팅에서 태오 팀장이 품질 점수 하락에 대해 "앞으로 신경 쓰겠습니다"라고 말합니다. 민석은 어떻게 할까요? |
| 보기 a (오답) | 신임 팀장이 의지를 보였으므로 격려하고 다음 마켓으로 넘어간다. |
| a 피드백 | 의지만으로는 다음 주에 확인할 것이 없습니다. 할 일과 기한으로 바꿔 적어야 합니다. |
| 보기 b (정답) | 무엇을 언제까지 할지 함께 정해, 담당과 기한을 미팅 기록에 적는다. |
| 보기 c (오답) | 미팅이 끝난 뒤 민석이 미국 마켓의 조치 계획을 대신 짜서 보내 준다. |
| c 피드백 | 대신 짜 주면 태오가 계획을 세우는 법을 배우지 못합니다. 미팅 자리에서 함께 정합니다. |
| 해설 | 조치는 할 일, 담당, 기한이 있어야 다음 주에 확인할 수 있습니다. |
| 2번 질문 | 주간 미팅은 무엇으로 시작하는 것이 좋을까요? |
| 보기 a (정답) | 지난주에 정한 조치가 끝났는지부터 확인한다. |
| 보기 b (오답) | 이번 주 숫자가 가장 나쁜 마켓부터 원인을 듣는다. |
| b 피드백 | 지난주 조치를 확인하지 않으면 같은 문제를 매주 처음부터 다시 이야기하게 됩니다. |
| 보기 c (오답) | 회사와 고객사의 새 공지를 먼저 길게 전한다. |
| c 피드백 | 공지는 따로 전할 수 있습니다. 미팅 시간은 지표와 조치에 먼저 씁니다. |
| 해설 | 지난주 조치를 먼저 확인해야 조치가 끝까지 이어집니다. |
| 다음 레슨 연결 | 미팅 밖에서도 위에서 내려오는 지침은 끝까지 전해야 합니다. 다음은 지침 전달과 확인 보고 절차입니다. |

## 레슨 2. 지침 전달과 확인 보고

| 항목 | 한국어 |
|---|---|
| 제목 | 지침 전달과 확인 보고 |
| 짧은 이름 | 지침 전달 |
| 부제 | 정리본 하나로 보내고, 확인 명단을 받아 보고합니다. |
| 누가 | 고객사·매니저 → 부매니저 → 팀장 → 상담사 |
| 노드 | 정리본 만들기 · 보내기 · 확인 명단 받기 · 결과 보고 |

스텝:

1. 이 절차의 목적은 고객사·매니저·회사의 지침이 모든 마켓의 상담사까지 닿았는지 확인하고, 그 결과를 매니저에게 보고하는 것입니다.
2. 첫 단계는 정리본 만들기입니다. 무엇이 바뀌는지, 언제부터인지, 누구에게 해당하는지, 고객에게 어떻게 안내하는지를 한 장에 적습니다. 헷갈리는 곳은 보내기 전에 정은 매니저에게 확인합니다.
3. 둘째 단계는 보내기입니다. 세 마켓 팀장에게 같은 정리본을 같은 시각에 보내고, 마켓마다 다른 점은 따로 표시합니다. 팀장은 허들과 팀 채팅방으로 상담사에게 전합니다.
4. 셋째 단계는 확인 명단 받기입니다. 팀장마다 상담사 이름, 확인 여부, 확인 방법을 적은 명단을 시행 하루 전(예시)까지 받습니다. 휴무나 휴가인 상담사는 복귀 첫 근무 전 전달 계획을 함께 받습니다.
5. 태오 팀장은 명단 없이 "공지 완료"라고만 보냈습니다. 민석은 같은 양식의 명단을 다시 요청하고, 빠진 인원이 있으면 누가 언제 전할지 정하게 합니다.
6. 넷째 단계는 결과 보고입니다. 마켓별 확인 비율, 아직 못 받은 인원과 전달 계획을 정은 매니저에게 보고합니다. 매니저는 이 보고로 고객사에 준비 상황을 답합니다.
7. 시행 첫날에는 직무전문가에게서 바뀐 안내와 관련된 질문이나 실수가 있었는지 짧게 받아, 필요하면 정리본을 고쳐 다시 보냅니다.
8. 미소의 한마디: "다들 알죠?"라고 물으면 모두 고개를 끄덕여요. 이름이 적힌 명단을 받기 시작한 뒤로는 월요일 아침이 조용해졌어요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 태오 팀장이 확인 명단 없이 "공지 완료"라고만 보냈습니다. 시행은 내일입니다. 어떻게 할까요? |
| 보기 a (오답) | 공지를 올렸다는 말을 믿고, 미국 마켓도 전달이 끝났다고 보고한다. |
| a 피드백 | 공지와 확인은 다릅니다. 명단 없이 보고하면 누가 모르는지 아무도 알 수 없습니다. |
| 보기 b (오답) | 민석이 미국 마켓 상담사에게 직접 메시지를 보내 한 명씩 확인한다. |
| b 피드백 | 팀장을 건너뛰면 태오가 명단 받는 법을 배우지 못하고, 다음에도 같은 일이 생깁니다. |
| 보기 c (정답) | 같은 양식의 명단을 다시 받고, 빠진 인원의 전달 계획을 정하게 한다. |
| 해설 | 전달은 이름이 적힌 확인 명단과, 빠진 인원의 계획까지 받아야 끝납니다. |
| 2번 질문 | 지침 정리본에 꼭 들어가야 하는 것은 무엇일까요? |
| 보기 a (오답) | 지침이 나오게 된 고객사 내부 사정과 회의 기록 전문 |
| a 피드백 | 배경은 필요할 때 따로 설명하면 됩니다. 상담사가 바로 쓸 수 있는 내용이 먼저입니다. |
| 보기 b (정답) | 바뀌는 내용, 시작일, 해당 대상, 고객 안내 방법 |
| 보기 c (오답) | 지침을 어겼을 때 받게 되는 감점과 벌칙 목록 |
| c 피드백 | 벌칙부터 보여 주면 무엇을 해야 하는지가 묻힙니다. 바르게 안내하는 방법을 먼저 적습니다. |
| 해설 | 정리본은 상담사가 바로 안내할 수 있게 무엇, 언제, 누구, 어떻게를 담습니다. |
| 다음 레슨 연결 | 아래에서 올라오는 것도 점검합니다. 다음은 팀장의 고객사 에스컬레이션 보고 점검 절차입니다. |

## 레슨 3. 에스컬레이션 보고 점검

| 항목 | 한국어 |
|---|---|
| 제목 | 에스컬레이션 보고 점검 |
| 짧은 이름 | 보고 점검 |
| 부제 | 분류와 보고 내용을 점검하고, 여러 마켓의 같은 문제는 묶습니다. |
| 누가 | 직무전문가 → 팀장 → 고객사 (부매니저 점검) |
| 노드 | 분류 확인 · 내용 점검 · 묶음 판단 · 기록 남기기 |

스텝:

1. 이 절차의 목적은 팀장이 고객사에 보내는 에스컬레이션 보고가 바르게 분류되고, 빠짐없이 쓰였는지 점검하는 것입니다.
2. 직무전문가가 상담사의 에스컬레이션과 고객 클레임을 모아 팀장에게 보고하고, 팀장은 메일이나 고객사와 정한 주기로 고객사에 보고합니다. 팀장이 고객사에 보내기 전에, 민석은 그 보고를 매일 저녁(예시) 함께 받아 봅니다.
3. 첫 단계는 분류 확인입니다. 센터 안에서 해결할 건과 고객사에 보고할 건이 고객사와 정한 기준대로 나뉘었는지 봅니다. 정책 예외, 시스템 오류, 개인정보 관련 건은 대개 고객사 보고 건입니다.
4. 둘째 단계는 내용 점검입니다. 고객 정보, 일어난 일, 지금까지의 조치, 고객사에 요청하는 것이 모두 들어갔는지 봅니다. 빠진 것이 있으면 민석이 고치지 않고 팀장에게 돌려보냅니다.
5. 셋째 단계는 묶음 판단입니다. 같은 문제가 두 마켓 이상에서 나오면 따로 보고하지 않고 한 건으로 묶어 규모와 함께 보고하게 합니다. 시스템 오류처럼 큰 건은 정은 매니저에게도 바로 알립니다.
6. 하린이 올린 한국 마켓 건 중 개인정보 관련 건이 자체 해결로 분류되어 있었습니다. 민석은 수진 팀장과 기준을 다시 보고 고객사 보고 건으로 옮기게 합니다.
7. 넷째 단계는 기록 남기기입니다. 보고한 건, 고객사의 답, 처리 결과와 걸린 시간을 마켓별 기록에 남깁니다. 이 기록은 비즈니스 리뷰의 숫자와 사례가 됩니다.
8. 미소의 한마디: 보고서를 제가 고쳐서 보내 주다 보니 팀장들은 무엇이 틀렸는지 몰랐어요. 돌려보내며 빠진 항목만 짚어 주니 두 달 만에 고칠 게 거의 없어졌어요.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 수진 팀장의 보고에 "고객사에 요청하는 것"이 빠져 있습니다. 보고 마감까지 한 시간(예시) 남았습니다. 어떻게 할까요? |
| 보기 a (오답) | 시간이 없으므로 민석이 요청 사항을 직접 써 넣어 보낸다. |
| a 피드백 | 대신 고치면 팀장은 무엇이 빠졌는지 모른 채 다음에도 같은 보고를 씁니다. |
| 보기 b (정답) | 빠진 항목을 짚어 수진 팀장에게 돌려보내고, 마감 안에 다시 받는다. |

## 레슨 4. 리스크 관리 대장

| 항목 | 한국어 |
|---|---|

| 짧은 이름 | 리스크 대장 |
| 부제 | 아직 터지지 않은 위험을 적고, 담당과 대응을 정해 매주 갱신합니다. |
| 누가 | 팀장 → 부매니저 → 매니저 |
| 노드 | 찾기 · 등급 매기기 · 담당 정하기 · 매주 갱신 |

스텝:

1. 이 절차의 목적은 아직 문제가 되지 않은 위험을 미리 적어 두고, 담당과 대응을 정해 매니저가 판단할 수 있게 하는 것입니다.
2. 첫 단계는 찾기입니다. 주간 미팅, 에스컬레이션 기록, 근태와 퇴사 예정, 고객사의 변경 예고에서 위험을 찾습니다. 유키 팀장이 다음 달 일본 마켓 상담사 2명(예시)의 퇴사 예정을 알려 왔습니다.
3. 둘째 단계는 등급 매기기입니다. 일어날 가능성과 일어났을 때의 영향을 각각 높음·중간·낮음으로 적습니다. 둘 다 높으면 매니저에게 바로 알릴 건입니다.
4. 셋째 단계는 담당 정하기입니다. 위험마다 담당자, 줄이는 방법, 확인할 날짜를 적습니다. 일본 마켓 건은 유키 팀장이 담당하고, 채용 요청과 다른 마켓 지원 가능 인원을 확인합니다.
5. 평소 채용이나 비용이 걸린 대응은 민석이 정하지 않습니다. 선택지와 숫자를 정리해 정은 매니저에게 올리고, 매니저가 정합니다.
6. 넷째 단계는 매주 갱신입니다. 주간 미팅 뒤 대장을 열어 새 위험을 더하고, 끝난 위험은 닫고, 등급이 바뀐 위험은 고칩니다.
7. 대장은 정은 매니저와 매주 1:1(예시)에서 함께 봅니다. 높은 등급 위험은 비즈니스 리뷰 전에 고객사에 미리 알릴지 매니저가 판단합니다.
8. 미소의 한마디: 퇴사 예정을 알고도 적어 두지 않았다가, 한 달 뒤 응대율이 무너지고 나서야 보고한 적이 있어요. 적어 두는 것만으로도 매니저가 미리 움직일 수 있었어요.

## 레슨 5. 비즈니스 리뷰 자료 준비

| 항목 | 한국어 |

| 누가 | 팀장·WFM → 부매니저 → 매니저 |
| 노드 | 일정 역산 · 숫자 검증 · 예상 질문 · 넘기기 |

스텝:

1. 이 절차의 목적은 WBR·MBR·QBR에서 매니저가 발표할 자료를 정해진 일정대로, 같은 기준의 숫자로 준비하는 것입니다.
2. 첫 단계는 일정 역산입니다. 미팅 날부터 거꾸로 자료 요청일, 마감일, 검토일, 매니저 전달일을 정합니다. MBR이라면 사흘 전(예시) 자료 마감, 하루 전 매니저 전달처럼 매달 같게 둡니다.
3. 민석은 팀장과 WFM 담당자에게 지난번과 같은 양식과 같은 기간 기준으로 요청합니다. 양식이 바뀌면 지난달과 비교할 수 없습니다.
4. 둘째 단계는 숫자 검증입니다. 기간과 기준이 같은지, 지난 보고서와 이어지는지, 시스템 자료와 맞는지 확인합니다. 어긋난 숫자는 그 마켓 팀장과 함께 다시 계산합니다.
5. 셋째 단계는 예상 질문입니다. 목표에서 벗어난 숫자마다 고객사가 물을 질문과 답할 사람을 적습니다. 마켓 상세 질문은 그 마켓 팀장이 답하고, 바로 답하기 어려운 질문은 미팅 뒤에 보내기로 미리 맞춥니다.
6. 넷째 단계는 넘기기입니다. 정은 매니저에게 자료와 함께 바뀐 숫자, 질문이 나올 만한 곳, 답할 사람을 한 장으로 보냅니다.
7. 미팅이 끝나면 남은 질문 목록을 만들어 담당 팀장과 기한을 정하고, 확인된 답을 매니저의 확인을 거쳐 이메일이나 채팅으로 보냅니다.
8. 미소의 한마디: 매달 일정을 새로 잡다 보니 늘 전날 밤에 숫자를 맞췄어요. 미팅 날부터 거꾸로 날짜를 고정하고 나서야 검토할 시간이 생겼어요.

## 레슨 6. 고객사 요청 정보 취합

| 항목 | 한국어 |

| 노드 | 요청 정리 · 양식과 마감 · 검토 · 확인 뒤 전달 |

스텝:

1. 이 절차의 목적은 고객사가 요청한 정보를 팀장들에게서 모아, 매니저의 확인을 거쳐 정해진 경로로 전달하는 것입니다.
2. 첫 단계는 요청 정리입니다. 무엇을, 어느 기간으로, 어떤 형식으로, 언제까지 원하는지 적습니다. 모호하면 추측하지 않고 매니저를 통해 고객사에 먼저 묻습니다.
3. 둘째 단계는 양식과 마감입니다. 민석은 세 마켓 팀장에게 같은 양식을 보내고, 마감은 고객사 기한보다 하루(예시) 앞으로 같은 날에 둡니다.
4. 셋째 단계는 검토입니다. 숫자의 기간과 기준이 같은지, 사례에 정해진 범위를 넘는 개인정보가 없는지 봅니다. 유키 팀장의 사례에 고객 이름이 남아 있어 지워서 다시 보내 달라고 합니다.
5. 넷째 단계는 확인 뒤 전달입니다. 하나로 묶은 자료를 정은 매니저에게 보내 확인을 받습니다. 매니저가 자리에 없으면 메신저나 메일로 요점을 보내 확인을 받습니다.
6. 확인을 받은 자료는 고객사와 정한 경로로 보내고, 보낸 내용과 시각을 요청 기록에 남깁니다.
7. 같은 요청이 매달 되풀이되면 양식을 고정해 두고, 팀장들에게 미리 알려 매달 같은 날 받습니다.
8. 미소의 한마디: 급해서 매니저 확인 없이 보냈다가 고객사에 두 가지 숫자가 간 적이 있어요. 아무리 급해도 확인 한 번은 꼭 받으세요.

## 레슨 7. 팀장 휴가와 백업 지정

| 노드 | 미리 신청 · 백업 지정 · 인수인계 · 복귀 확인 |

스텝:

1. 이 절차의 목적은 팀장이 휴가나 교육으로 자리를 비우는 동안 팀이 흔들리지 않게 백업을 정하고, 인수인계를 확인하는 것입니다.
2. 첫 단계는 미리 신청입니다. 팀장은 정해진 기한(예시: 2주 전)까지 민석에게 휴가를 신청합니다. 민석은 같은 기간에 다른 팀장의 휴가와 고객사 일정이 겹치지 않는지 봅니다.
3. 둘째 단계는 백업 지정입니다. 수진 팀장의 휴가 동안 하린 직무전문가가 허들, 실시간 응대 관리, 상담사 질문 같은 현장 실무를 대행합니다. 팀원과 마켓 정보의 취합, 보고서 제출, 고객사 보고는 민석이 대행합니다.
4. 셋째 단계는 인수인계입니다. 수진 팀장은 현장 일은 하린에게, 보고 일정과 양식은 민석에게 넘깁니다. 진행 중인 코칭, 에스컬레이션, 주의할 팀원 목록은 셋이 함께 봅니다.
5. 신임 팀장 태오가 휴가를 갈 때는 경험이 있는 유키 팀장이 미국 마켓의 백업 직무전문가에게 현장 조언을 해 주게 하는 것도 방법입니다. 취합과 보고는 그대로 민석이 맡고, 백업이 처음인 사람에게는 하루 한 번(예시) 상황을 묻습니다.
6. 넷째 단계는 복귀 확인입니다. 팀장이 돌아오면 하린은 현장에서 있었던 일과 남은 일을, 민석은 대신 낸 보고와 고객사의 답을 넘깁니다.
7. 백업을 맡은 하린의 경험은 팀장 승진 준비의 기록이 됩니다. 민석은 잘한 점과 다음에 더 맡겨 볼 일을 적어 둡니다.
8. 미소의 한마디: 보고까지 직무전문가에게 맡겼더니, 팀장 휴가 중에 고객사 주간 보고가 빠졌어요. 그 뒤로 현장은 백업에게, 보고는 제가 맡았어요.

## 레슨 8. 매니저 대행 인수인계

| 항목 | 한국어 |
|---|---|
| 제목 | 매니저 대행 인수인계 |
| 짧은 이름 | 매니저 대행 |
| 부제 | 대행 범위를 정해 받고, 대행 기록을 남겨 돌려줍니다. |
| 누가 | 매니저 → 부매니저 → 매니저 |
| 노드 | 범위 정하기 · 대행 기록 · 확인 뒤 답하기 · 돌려주기 |

스텝:

1. 이 절차의 목적은 매니저가 자리를 비우는 동안 정해진 범위 안에서 대신하고, 그동안의 일을 빠짐없이 돌려주는 것입니다.
2. 첫 단계는 범위 정하기입니다. 정은 매니저의 휴가 전에 민석이 정해도 되는 것, 매니저에게 물어야 하는 것, 긴급할 때 연락 방법을 한 장에 적어 둘이 함께 확인합니다.
3. 손익과 계약의 결정은 대행 범위에 넣지 않습니다. 인력 계획, SLA 관리, 위기 대응은 매니저와 미리 정한 범위 안에서 민석이 대행할 수 있습니다. 범위 밖의 질문은 확인할 날짜를 정해 답합니다.
4. 둘째 단계는 대행 기록입니다. 고객사 미팅, 받은 요청, 민석이 정한 것, 매니저에게 물은 것을 날짜별로 한 문서에 적습니다.
5. 셋째 단계는 확인 뒤 답하기입니다. 범위 밖의 질문은 그날 안에 요점을 매니저에게 보내고, 답을 받아 약속한 날 고객사에 전합니다.
6. 고객사 미팅에는 마켓 팀장들과 함께 들어갑니다. 대행 중 위기가 생기면 정해 둔 위기 대응 절차대로 먼저 움직이고, 매니저에게 요점을 바로 알립니다.
7. 넷째 단계는 돌려주기입니다. 매니저가 돌아온 날 대행 기록을 넘기며 새로 한 약속, 남은 질문, 매니저가 정해야 할 일을 짚습니다.
8. 미소의 한마디: 대행이 끝나고 기억으로만 설명했더니 매니저가 고객사와 다른 이야기를 할 뻔했어요. 날짜별 기록 하나가 그날을 살렸어요.

| 항목 | 한국어 |

| 1번 질문 | 대행 중 고객사가 다음 분기 계약 단가를 조정할 수 있느냐고 묻습니다. 어떻게 할까요? |
