## 레슨 1. SME가 된 첫날

| 항목 | 한국어 |
|---|---|
| 제목 | SME가 된 첫날 |
| 짧은 이름 | 첫날 |
| 부제 | 내 자리가 무엇이고, 어디까지 내가 정하는지. |
| 노드 | 역할 알기 · 하루 일과 · 승인 범위 · 팀장과 나누기 |

스텝:

1. 이 레슨의 목적은 상담사에서 SME가 된 첫날, 내 자리가 무엇이고 하루를 어떻게 쓰며 어디까지 내가 정하는지 아는 것입니다. 네 단계로 살펴봅니다.
2. 어제까지 당신은 수진 팀의 선임 상담사였습니다. 오늘부터는 같은 팀 12명(예시)을 받쳐 주는 SME입니다. 이제는 내 문의를 잘 처리하는 것보다 팀이 막히지 않게 하는 것이 일입니다.
3. 첫 단계는 역할 알기입니다. SME는 팀의 지식 허브입니다. 막힌 문의에 답을 주고, 에스컬레이션을 승인하거나 처리하고, 동료의 성장을 돕습니다.
4. SME는 상담사를 평가하거나 징계하는 자리가 아닙니다. 평가는 QA와 팀장이 맡습니다. 당신은 승인하고 돕는 사람입니다.
5. 둘째 단계는 하루 일과 알기입니다. 하루의 대부분은 에스컬레이션 지원과 어려운 케이스 처리, 상담사 멘토링에 씁니다. 여기에 VOC 정리와 QA와의 품질 교정 미팅이 더해집니다.
6. 서포트 요청은 두 곳에서 옵니다. 플로어를 돌며 손을 든 상담사를 돕고, 메신저와 팀 채팅방으로 들어오는 질문에도 답합니다.
7. 셋째 단계는 승인 범위 확인입니다. 첫날 수진 팀장과 앉아, 내가 승인할 수 있는 것과 팀장에게 넘길 것을 목록으로 맞춥니다. 예를 들어 정해진 기준 안의 보상은 승인하고, 정책 밖의 요청과 근태·성과 문제는 넘깁니다.
8. 범위를 모르면 두 가지 실수가 생깁니다. 내 권한 밖을 승인해 버리거나, 반대로 모든 건을 팀장에게 넘겨 팀장의 하루가 막힙니다.
9. 넷째 단계는 팀장과 나누기입니다. 팀장이 바쁠 때 출석 관리, 코칭 자료, 허들을 나눠 맡을 수 있다는 것도 미리 이야기해 둡니다. 레슨 5에서 자세히 다룹니다.
10. 첫날이 끝나면 오늘 받은 질문을 짧게 적어 둡니다. 자주 오는 질문이 내일 먼저 준비할 것입니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 첫날, 상담사가 고객에게 정책에 없는 큰 보상을 해 주자며 승인을 요청합니다. 어떻게 할까요? |
| 보기 a (오답) | 고객이 화가 많이 났으니 일단 승인한다. |
| a 피드백 | 승인 범위 밖의 결정은 되돌리기 어렵고, 다른 고객에게도 같은 기준을 요구받게 됩니다. |
| 보기 b (정답) | 승인 범위 밖이므로 고객에게 기다림을 안내하게 하고, 팀장에게 바로 넘긴다. |
| 보기 c (오답) | 정책에 없으니 거절하고 상담사에게 그대로 응대하게 한다. |
| c 피드백 | 거절로 끝내면 고객의 문제는 그대로 남습니다. 내가 정할 수 없는 건은 정할 수 있는 사람에게 넘깁니다. |
| 해설 | 승인 범위 안은 내가 정하고, 범위 밖은 팀장에게 넘깁니다. 첫날 범위를 맞춰 두는 이유입니다. |
| 2번 질문 | 지민의 응대 태도가 요즘 걱정됩니다. SME로서 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 지민의 품질 점수를 직접 낮춰 기록한다. |
| a 피드백 | 평가는 QA와 팀장이 맡습니다. SME가 점수를 매기면 역할이 섞여 지민도 누구에게 도움을 청할지 헷갈립니다. |
| 보기 b (정답) | 옆에서 응대를 함께 보며 돕고, 같은 모습이 반복되면 팀장에게 사례와 함께 알린다. |
| 보기 c (오답) | SME가 관여할 일이 아니니 모른 척한다. |
| c 피드백 | 돕는 것은 SME의 일입니다. 모른 척하면 문제가 커진 뒤에야 드러납니다. |
| 해설 | SME는 평가 대신 돕고, 반복되는 문제는 근거와 함께 팀장에게 전합니다. |
| 다음 레슨 연결 | 역할을 알았으니 이제 사람을 만날 차례입니다. 먼저 가장 가까이 붙어 있어야 할 사람, 막 교육을 마친 신입입니다. |

## 레슨 2. 신입 상담사 서포트

| 항목 | 한국어 |
|---|---|
| 제목 | 교육 중·막 교육을 마친 상담사 서포트 |
| 짧은 이름 | 신입 서포트 |
| 부제 | 질문을 기다리지 말고 먼저 다가갑니다. |
| 노드 | 미리 알기 · 옆에 붙기 · 먼저 확인 · 팀장에게 공유 |

스텝:

1. 이 레슨의 목적은 교육 중이거나 막 교육을 마친 상담사가 실제 문의에 적응하도록 돕는 것입니다. 이 시기는 상담사가 가장 많이 떠나는 시기입니다.
2. 서준은 지난주 교육을 마치고 오늘 처음 팀에 합류했습니다. 지식은 있지만 실제 고객 앞에 서는 것은 처음입니다.
3. 첫 단계는 미리 알기입니다. 트레이너에게 서준이 교육에서 어려워한 부분을 미리 듣고, 오늘 들어올 문의 중 서준에게 어려울 만한 유형을 떠올려 둡니다.
4. 둘째 단계는 옆에 붙기입니다. 첫 며칠(예시)은 서준 자리 가까이 있으며 첫 몇 건을 함께 봅니다. 전화는 같이 듣고, 채팅과 이메일은 보내기 전에 함께 읽습니다.
5. 답을 바로 주기보다 어디서 찾는지 보여 줍니다. 지식 베이스의 어느 문서에 있는지 알려 주면 다음에는 혼자 찾을 수 있습니다.
6. 셋째 단계는 먼저 확인하기입니다. 신입은 질문하는 것 자체를 망설입니다. 손을 들 때까지 기다리지 말고, 정해진 간격(예시: 1시간에 한 번)으로 먼저 다가가 묻습니다.
7. 실수는 그 자리에서 짧게 고쳐 주고, 잘한 것도 바로 말해 줍니다. 이 시기에는 칭찬 한마디가 버티는 힘이 됩니다.
8. 교육 중인 상담사(OJT)와 막 교육을 마친 상담사는 붙어 있는 거리가 다릅니다. OJT 기간에는 트레이너와 함께 보고, 네스팅부터는 SME가 더 가까이 붙습니다.
9. 넷째 단계는 팀장에게 공유하기입니다. 하루가 끝나면 서준이 무엇을 잘했고 어디서 막혔는지 팀장과 트레이너에게 짧게 전합니다. 평가가 아니라 다음 날 도울 곳을 정하기 위해서입니다.
10. 같은 곳에서 계속 막히면 추가 교육이 필요할 수 있습니다. 결정은 팀장과 트레이너가 하고, 당신은 근거가 될 사례를 모읍니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 서준이 오전 내내 한 번도 질문하지 않았습니다. 어떻게 할까요? |
| 보기 a (오답) | 잘하고 있다는 뜻이니 그대로 둔다. |
| a 피드백 | 신입이 조용한 것은 잘해서가 아니라 묻기를 망설여서일 때가 많습니다. |
| 보기 b (정답) | 먼저 다가가 오전에 받은 문의가 어땠는지 묻는다. |
| 보기 c (오답) | 질문을 하지 않는다고 팀장에게 알린다. |
| c 피드백 | 아직 무슨 일인지 모르는 상태입니다. 먼저 서준에게 직접 묻는 것이 순서입니다. |
| 해설 | 신입 서포트는 기다리는 것이 아니라 먼저 다가가는 것입니다. |
| 2번 질문 | 서준이 같은 절차를 세 번째 묻습니다. 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 이번에도 바로 답을 알려 준다. |
| a 피드백 | 답만 주면 스스로 찾는 힘이 생기지 않아, 네 번째 질문도 오게 됩니다. |
| 보기 b (정답) | 지식 베이스에서 함께 찾아 보여 주고, 반복되는 부분을 팀장과 트레이너에게 전한다. |
| 보기 c (오답) | 이미 알려 줬으니 혼자 찾아보라고 한다. |
| c 피드백 | 혼자 찾게 두면 고객이 그만큼 기다리고, 서준은 다시 묻기를 망설이게 됩니다. |
| 해설 | 찾는 방법을 보여 주고, 반복되는 어려움은 추가 교육의 근거로 전합니다. |
| 다음 레슨 연결 | 신입만 SME를 찾는 것은 아닙니다. 일이 익숙한 기존 상담사도 권한 밖의 문의를 들고 옵니다. |

## 레슨 3. 기존 상담사 서포트

| 항목 | 한국어 |
|---|---|
| 제목 | 기존 상담사 서포트 |
| 짧은 이름 | 에스컬레이션 |
| 부제 | 넘어온 건을 승인하거나, 처리하거나, 넘깁니다. |
| 노드 | 기록 확인 · 판단 · 답 돌려주기 · 팀에 나누기 |

스텝:

1. 이 레슨의 목적은 기존 상담사가 넘긴 문의와 에스컬레이션을 빠르게 판단해, 승인·직접 처리·팀장에게 넘기기 중 하나로 정리하는 것입니다.
2. 지민은 2년째 일하는 상담사입니다. 일은 익숙하지만, 오늘 받은 문의는 자기 권한으로 풀 수 없습니다. 지민이 메신저로 당신에게 승인을 요청합니다.
3. 첫 단계는 기록 확인입니다. 티켓에 고객이 원하는 것, 지민이 이미 해 본 것, 고객의 감정 상태가 적혀 있는지 봅니다.
4. 기록이 부족하면 지민에게 짧게 다시 묻습니다. 고객에게 같은 질문을 되풀이하지 않기 위해서입니다.
5. 둘째 단계는 판단입니다. 내 승인 범위 안이면 승인하고, 직접 응대가 필요하면 내가 이어서 처리하고, 범위 밖이면 팀장에게 넘깁니다.
6. 승인할 때는 이유도 함께 적어 둡니다. 비슷한 요청이 다시 오면 다른 사람도 같은 기준으로 판단할 수 있습니다.
7. 직접 처리할 때는 고객에게 이전 내용을 알고 있다고 먼저 말합니다. 넘겨받은 사람이 처음부터 다시 묻는 것을 고객은 가장 싫어합니다.
8. 셋째 단계는 답 돌려주기입니다. 처리가 끝나면 결과와 이유를 지민에게 알려 줍니다. 다음에 비슷한 건이 오면 지민이 혼자 풀 수 있습니다.
9. 넷째 단계는 팀에 나누기입니다. 같은 질문이 여러 상담사에게서 오면, 허들이나 팀 채팅방에 한 번에 정리해 공유합니다.
10. 기존 상담사는 답을 빨리 원합니다. 판단이 길어지면 "5분 안에 답 드릴게요"(예시)처럼 언제 답할지 먼저 알려 줍니다.

스텝:

1. 이 레슨의 목적은 동료였던 선임 상담사도 다른 상담사와 같은 기준으로 승인하고 도우며, 서로 존중하는 관계로 옮겨 가는 것입니다.
2. 준호는 당신과 같은 날 입사한 동기이고, 성적도 비슷했습니다. 이제 준호도 에스컬레이션 승인이 필요하면 당신에게 요청해야 합니다.
3. 어색함은 양쪽 모두 느낍니다. 준호는 동기에게 승인을 받는 것이, 당신은 동기의 요청을 판단하는 것이 불편할 수 있습니다.
4. 첫 단계는 관계 다시 맺기입니다. 첫 주에 준호와 따로 이야기합니다. 내 역할이 무엇인지, 도움이 필요할 때 어떻게 요청하면 좋은지 솔직하게 말합니다.
5. 둘째 단계는 같은 기준입니다. 준호의 요청도 다른 상담사와 같은 승인 기준으로 판단합니다. 친해서 쉽게 승인하면 다른 상담사들은 기준이 사람마다 다르다고 느낍니다.
6. 반대로 일부러 더 엄하게 대하는 것도 공정하지 않습니다. 기준은 같게 하고, 말투는 지금까지처럼 편해도 괜찮습니다.
7. 셋째 단계는 존중하며 돕기입니다. 선임 상담사는 아는 것이 많습니다. 가르치려 하기보다 준호의 판단을 먼저 묻고, 필요한 부분만 더합니다.
8. 준호의 경험은 팀의 자원입니다. 신입 서준의 질문을 함께 봐 달라고 부탁하거나, 어려운 케이스를 같이 검토하자고 요청할 수 있습니다.
9. 넷째 단계는 팀장과 상의하기입니다. 준호가 승인 없이 절차를 건너뛰는 일이 반복되면 혼자 해결하려 하지 말고 팀장과 상의합니다. 근태와 성과 문제는 팀장이 맡습니다.
10. 첫 주의 솔직한 대화가 출발점입니다. 시간이 지나면 동기였던 사이가 서로를 가장 잘 받쳐 주는 관계가 될 수 있습니다.

## 레슨 5. 팀장 서포트

| 항목 | 한국어 |
|---|---|
| 제목 | 팀장 서포트 |
| 짧은 이름 | 팀장 서포트 |
| 부제 | 출석 관리, 트렌드 요약, 허들을 나눠 맡습니다. |
| 노드 | 출석 관리 · 트렌드 요약 · 허들 진행 · 팀장에게 보고 |

스텝:

1. 이 레슨의 목적은 팀장의 일을 부분적으로 나눠 맡아, 팀장이 코칭과 팀 관리에 시간을 쓰도록 돕는 것입니다. 대표적인 일은 세 가지입니다.
2. 수진 팀장은 15명(예시) 팀을 맡고 있고, 오늘은 오후 내내 고객사 미팅에 들어갑니다.
3. 첫째는 출석 관리입니다. 팀원이 많거나 팀장이 자리에 없을 때 SME가 출석을 대신 확인합니다. 근무 시작 시각에 자리에 없는 사람과 지각, 결근 연락을 기록합니다.
4. 대행은 기록하고 알리는 데까지입니다. 사유를 판단하거나 근태 조치를 정하는 것은 팀장이 합니다. 결근이 늘어 인원이 부족하면 팀장과 RTA에게 바로 알립니다.
5. 둘째는 스크러빙 트렌드 요약입니다. 매일 스크러빙한 티켓에서 상담사별로 반복되는 모습을 모아, 팀장이 코칭에 바로 쓸 수 있게 짧게 정리합니다.
6. 요약은 사실과 사례로 씁니다. 예를 들어 "지민: 이번 주 환불 문의 3건에서 같은 확인 단계를 빠뜨림"처럼 쓰고 티켓 번호를 붙이면, 팀장이 코칭에 바로 씁니다.
7. 사람에 대한 평가 대신 행동을 적습니다. "꼼꼼하지 않다"가 아니라 "확인 단계를 건너뛰었다"고 씁니다.
8. 셋째는 허들 진행입니다. 고객사가 정책이나 프로모션 업데이트를 보내오면 SME가 허들에서 팀에 전합니다.
9. 허들 전에 내용을 먼저 이해하고, 상담사가 고객에게 어떻게 말하면 되는지까지 준비합니다. 허들에서 나온 질문은 답을 정리해 팀 채팅방에 다시 올립니다.
10. 마지막으로 팀장에게 보고합니다. 팀장이 돌아왔을 때 무엇이 있었는지 한눈에 알 수 있도록 출석, 요약, 허들 내용을 짧게 전합니다.

## 레슨 6. 요청이 동시에 몰릴 때

| 항목 | 한국어 |
|---|---|
| 제목 | 요청이 동시에 몰릴 때 |
| 짧은 이름 | 우선순위 |
| 부제 | 기다리는 고객부터, 아무도 버려졌다고 느끼지 않게. |
| 노드 | 급한 것 먼저 · 기다림 알리기 · 나눠 맡기기 · 팀장 부르기 |

스텝:

1. 이 레슨의 목적은 플로어와 온라인에서 요청이 한꺼번에 몰릴 때, 가장 급한 것부터 처리하고 아무도 버려졌다고 느끼지 않게 하는 것입니다.
2. 오전 11시(예시)입니다. 서준이 손을 들었고, 지민의 메신저가 깜박이고, 준호는 승인을 요청했고, 팀 채팅방에는 질문 두 개가 올라와 있습니다.
3. 첫 단계는 급한 것 먼저입니다. 기준은 고객이 지금 기다리고 있느냐입니다. 통화 중 보류된 고객, 실시간 채팅 중인 고객의 건이 먼저입니다.
4. 이메일과 티켓처럼 고객이 실시간으로 기다리지 않는 건, 그리고 일반 질문은 그다음입니다.
5. 급한 정도가 같다면 감정이 올라간 고객의 건과 신입의 건을 먼저 봅니다. 신입은 고객을 오래 붙잡고 있기 쉽기 때문입니다.
6. 둘째 단계는 기다림 알리기입니다. 바로 갈 수 없는 사람에게는 "2분 뒤에 갈게요"(예시)처럼 언제 갈지 먼저 알립니다. 답이 없는 것보다 기다릴 시간을 아는 것이 훨씬 낫습니다.
7. 셋째 단계는 나눠 맡기기입니다. 일반 질문은 준호 같은 선임 상담사에게 부탁하거나, 지식 베이스 문서 위치만 먼저 보내 줍니다.
8. 넷째 단계는 팀장 부르기입니다. 요청이 계속 쌓여 고객 대기가 길어지면 혼자 버티지 말고 팀장에게 알립니다. 팀장이 함께 서포트하거나 RTA와 인원을 조정할 수 있습니다.
9. 플로어와 온라인을 모두 놓치지 않으려면 방법을 정해 둡니다. 센터 규정이 허락하면 플로어를 돌 때도 메신저를 볼 수 있는 기기를 들고 다닙니다.
10. 바쁜 시간이 지나면 왜 몰렸는지 돌아봅니다. 같은 질문이 몰렸다면 허들 주제가 되고, 특정 시간대마다 몰린다면 팀장과 서포트 계획을 바꿉니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 통화 중 고객을 보류해 둔 서준과, 이메일 답변 문구를 확인받고 싶은 지민이 동시에 부릅니다. 어떻게 할까요? |
| 보기 a (오답) | 먼저 부른 사람부터 간다. |
| a 피드백 | 순서보다 고객이 지금 기다리고 있는지가 기준입니다. 보류된 고객은 1분마다 더 지칩니다. |
| 보기 b (정답) | 서준에게 먼저 가고, 지민에게는 언제 갈지 알려 준다. |
| 보기 c (오답) | 지민의 건이 금방 끝나니 지민부터 처리한다. |
| c 피드백 | 금방 끝나도 이메일은 기다릴 수 있습니다. 통화 중인 고객은 기다릴 수 없습니다. |
| 해설 | 실시간으로 기다리는 고객이 먼저이고, 기다리게 되는 사람에게는 언제 갈지 알립니다. |
| 2번 질문 | 30분째 요청이 계속 쌓이고 고객 대기가 길어지고 있습니다. 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 점심을 미루고 혼자 끝까지 처리한다. |
| a 피드백 | 혼자 버티는 동안 고객 대기는 더 길어지고, 팀장은 문제가 있다는 것도 모릅니다. |
| 보기 b (정답) | 팀장에게 상황을 알려 함께 대응한다. |
| 보기 c (오답) | 메신저를 잠시 끄고 플로어 요청만 처리한다. |
| c 피드백 | 온라인 요청 뒤에도 기다리는 고객이 있습니다. 요청을 안 보이게 해도 사라지지 않습니다. |
| 해설 | 혼자 감당할 수 없는 양이면 팀장에게 알립니다. 인원 조정은 팀장과 RTA가 할 수 있습니다. |
| 다음 레슨 연결 | 바쁜 하루가 지나고 나면 SME에게 남는 일이 있습니다. 오늘 본 것을 팀의 지식으로 돌려주는 일입니다. |

## 레슨 7. 팀에 지식 돌려주기

| 항목 | 한국어 |
|---|---|
| 제목 | 팀에 지식 돌려주기 |
| 짧은 이름 | 지식 돌려주기 |
| 부제 | 매일 스크러빙하고, 찾은 것을 팀에 돌려줍니다. |
| 노드 | 매일 스크러빙 · VOC 정리 · 캘리브레이션 · 팀에 돌려주기 |

스텝:

1. 이 레슨의 목적은 매일 하는 스크러빙과 VOC, 캘리브레이션으로 팀의 트렌드를 파악하고, 알게 된 것을 팀 전체에 돌려주는 것입니다.
2. 스크러빙은 SME의 주된 일입니다. 처리된 티켓과 쌓여 있는 티켓을 다시 읽고 진짜 원인을 찾습니다. 매일 몇 건씩(예시: 하루 3~4건) 꾸준히 합니다.
3. 첫 단계는 매일 스크러빙하기입니다. DSAT, CSAT, 미해결 순서로 티켓을 고르고, 원인을 한두 문장으로 요약해 정해진 분류로 나눕니다. 절차는 SOP 스크러빙에 있습니다.
4. 매일 조금씩 하는 이유는 트렌드가 쌓여야 보이기 때문입니다. 한 번에 몰아서 보면 원인이 겹치는 것을 놓치기 쉽고, 돌려주는 것도 늦어집니다.
5. 둘째 단계는 VOC 정리입니다. 고객이 반복해서 하는 말, 곧 불만과 요청과 제품에 대한 의견을 모아 정리합니다. 상담사가 바꿀 수 없는 원인은 고객사에 전할 내용이 됩니다.
6. 셋째 단계는 캘리브레이션입니다. QA, 팀장과 함께 같은 상담을 각자 평가하고 점수 차이를 맞춥니다. SME는 상담사가 현장에서 실제로 겪는 상황을 알려 주는 역할을 합니다.
7. 캘리브레이션에서 기준이 바뀌면 상담사들에게 먼저 전하는 사람도 SME입니다. 바뀐 기준을 모른 채 평가받는 상담사가 없게 합니다.
8. 넷째 단계는 팀에 돌려주기입니다. 찾은 것을 허들, 팀 채팅방, 지식 베이스 업데이트로 나눠 전합니다.
9. 한 사람의 실수가 원인이면 팀 앞이 아니라 팀장에게 건네는 요약(레슨 5)으로 보냅니다. 팀에는 누구의 건인지 밝히지 않고 배울 점만 나눕니다.
10. 돌려준 지식이 쌓이면 같은 질문이 줄고, 당신에게 오는 요청도 줄어듭니다. 이것이 SME가 팀을 키우는 방식입니다.

체크포인트:

| 항목 | 한국어 |
|---|---|
| 1번 질문 | 스크러빙에서 지민의 절차 실수로 생긴 DSAT를 찾았습니다. 어떻게 나눌까요? |
| 보기 a (오답) | 허들에서 지민의 건이라고 밝히고 사례로 설명한다. |
| a 피드백 | 이름이 나오면 지민은 창피를 당하고, 다른 상담사들은 실수를 숨기기 시작합니다. |
| 보기 b (정답) | 팀장에게 건넬 요약에 담고, 팀에는 이름 없이 배울 점만 나눈다. |
| 보기 c (오답) | 한 번의 실수이니 아무에게도 알리지 않는다. |
| c 피드백 | 같은 실수가 다른 상담사에게도 생길 수 있습니다. 배울 점은 팀에 돌려줘야 합니다. |
| 해설 | 개인의 건은 팀장에게, 배울 점은 이름 없이 팀에게 돌려줍니다. |
| 2번 질문 | 스크러빙을 매일 몇 건씩 꾸준히 하는 이유로 알맞은 것은 무엇일까요? |
| 보기 a (오답) | 하루에 해야 할 건수가 규칙으로 정해져 있어서. |
| a 피드백 | 건수는 센터마다 다른 예시입니다. 중요한 것은 매일 이어서 보는 것입니다. |
| 보기 b (정답) | 원인이 쌓여야 트렌드가 보이고, 찾은 것을 바로 팀에 돌려줄 수 있어서. |
| 보기 c (오답) | 바쁜 날 몰아서 해도 결과는 같지만 보고서 모양이 좋아서. |
| c 피드백 | 몰아서 하면 돌려주는 시점이 늦어지고, 그사이 같은 실수가 되풀이됩니다. |
| 해설 | 매일 조금씩 봐야 트렌드가 보이고, 지식을 제때 돌려줄 수 있습니다. |
| 마지막 연결 | SME 첫걸음을 마쳤습니다. 더 깊이 보고 싶다면 SOP 라이브러리의 스크러빙, 캘리브레이션, 기존 상담사 육성을 이어서 보세요. |
